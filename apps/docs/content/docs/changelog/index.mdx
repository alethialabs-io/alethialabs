title: Changelog

---

Alethia ships as three parts: the console (the web app and its API), the `alethia` CLI, and the
runner that executes jobs. The CLI and the runner each have a version and a changelog. The console
is identified by the commit it was built from.

## Version numbers

| Part | Version | Released as |
|---|---|---|
| CLI | Semantic version, `0.x.y` | A GitHub release on [`alethia-cli`](https://github.com/alethialabs-io/alethia-cli/releases), and Homebrew, Scoop and Linux packages |
| Runner | Semantic version, `0.x.y` | The image `ghcr.io/alethialabs-io/runner:<version>` |
| Console | The commit SHA | Images on `ghcr.io/alethialabs-io`, tagged with the SHA and `latest` |

While the CLI and the runner are on `0.x`, a minor release can contain breaking changes. Read the
changelog before you upgrade.

## Changelogs

Each changelog lists every change by type, with a link to its pull request. It is generated from
the commit history at each release.

- **CLI:** [`apps/cli/CHANGELOG.md`](https://github.com/alethialabs-io/alethialabs/blob/main/apps/cli/CHANGELOG.md)
- **Runner:** [`apps/runner/CHANGELOG.md`](https://github.com/alethialabs-io/alethialabs/blob/main/apps/runner/CHANGELOG.md)

Read them on the `main` branch; copies on other branches can be out of date. Product news is at
[`/news`](https://alethialabs.io/news).

## Platform releases

A platform release will name one console build, one CLI version and one runner version that were
tested together, with breaking changes and upgrade steps. None is published yet. Until then, a
self-hosted instance runs the image tag recorded as `ALETHIA_VERSION` in its `.env`: see
[Upgrade and back up](/self-host/upgrading).

## Check the version you run

```bash
alethia version
```

This prints the CLI's version, the commit it was built from, and whether a newer release exists. For
a runner, read the image tag of its container.
