---
title: Keyless cloud connectors
description: What a self-hosted instance needs so that users can connect AWS, GCP and Azure without keys, and how to rotate the issuer key those clouds trust.
---

Let your users connect AWS, GCP and Azure accounts with no stored key. Each instance is its own
OpenID Connect (OIDC) issuer. A user's cloud trusts that issuer, and Alethia exchanges a short-lived
signed assertion for cloud credentials when it needs them. You do not need a cloud account of your
own. How the trust works on each cloud is in [Security](/concepts/security#the-issuer).

Hetzner is not keyless: the user pastes an API token, which Alethia stores encrypted. It needs
nothing on this page.

## Before you begin

- `ALETHIA_OIDC_SIGNING_KEY` is set. The installer generates it.
- `NEXT_PUBLIC_APP_URL` is an `https://` address that the internet can reach. AWS, GCP and Azure
  fetch the issuer's public keys from it.

The issuer is `<NEXT_PUBLIC_APP_URL>/api/oidc`. Its discovery document is at
`/api/oidc/.well-known/openid-configuration`, and its public keys at `/api/oidc/jwks`.

## Check that the issuer is reachable

From a machine outside your network:

```bash
curl -fsS https://alethia.example.com/api/oidc/.well-known/openid-configuration
curl -fsS https://alethia.example.com/api/oidc/jwks
```

Both return JSON. Then open **Connectors** in the console: the AWS, GCP and Azure cards offer
**Connect**.

If the console instead says the instance cannot serve a keyless connect, it names one reason:

| Reason | Fix |
| --- | --- |
| no issuer signing key | Set `ALETHIA_OIDC_SIGNING_KEY`. Run the installer again to generate it. |
| no public URL configured | Set `NEXT_PUBLIC_APP_URL`. |
| the URL is not HTTPS | Give the instance a domain with TLS. See [Install on a VM](/self-host/install). |
| a private or local address | Publish the console on a public address, or use a token cloud or a [self-operated runner](/guides/runners/self-operated) that holds its own cloud credentials. |

## What the user does

The user runs a setup script or OpenTofu module in their own account, which trusts your issuer, and
pastes the result into the console. See [Connect AWS](/guides/connectors/aws),
[Connect GCP](/guides/connectors/gcp) and [Connect Azure](/guides/connectors/azure). On Azure the
federated credential names issuer `<NEXT_PUBLIC_APP_URL>/api/oidc`, subject `alethia-connector` and
audience `api://AzureADTokenExchange`.

<Callout type="warn">
  Every user connection trusts your issuer's URL. If `NEXT_PUBLIC_APP_URL` changes, every user must
  run their setup again.
</Callout>

## Rotate the issuer signing key

The signing key is the trust root for every keyless connection, so rotate it with an overlap:

1. Run the rotation script:

   ```bash
   sh /opt/alethia/deploy/selfhost/rotate-secret.sh ALETHIA_OIDC_SIGNING_KEY
   ```

   The old key moves to `ALETHIA_OIDC_SIGNING_KEY_PREVIOUS`. The issuer publishes both keys and
   signs with the new one.

2. Wait at least 24 hours, so every cloud refreshes its copy of the keys and every old assertion has
   expired.
3. Delete `ALETHIA_OIDC_SIGNING_KEY_PREVIOUS` from `.env`, and restart the console.

No change is needed in your users' clouds.
