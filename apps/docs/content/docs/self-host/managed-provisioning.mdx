---
title: Managed provisioning
description: Run a fleet of Hetzner runner VMs that your instance scales by queue depth, so your users' plan and deploy jobs run without a runner of their own.
---

Run the jobs for your users. Your instance creates runner VMs on Hetzner Cloud, each one claims a
job, signs in to the user's cloud with that job's own short-lived credential, runs OpenTofu, and
streams the log and the state back. Users never run a runner.

## How a job runs

1. A user connects a cloud and starts a plan or a deploy.
2. Every 60 seconds the scaler compares the queue with each pool, and creates a Hetzner VM when a
   pool needs one. The VM pulls `ghcr.io/alethialabs-io/runner-<cloud>` and registers with a
   one-time token that expires.
3. The runner claims the job. It gets a credential for the user's cloud (keyless on AWS, GCP and
   Azure; the user's API token on Hetzner) and a credential for that job's OpenTofu state. State
   goes through the console; the VM never holds a storage key.
4. The job ends, and the VM takes the next job or is removed. A VM runs one job at a time by
   default.

## Before you begin

- A working install with a public HTTPS address. See [Install on a VM](/self-host/install).
- Keyless connectors working, if you offer AWS, GCP or Azure. See
  [Keyless cloud connectors](/self-host/managed-cloud-connectors).
- A Hetzner Cloud project for the fleet, and an API token for it. Keep it apart from any project a
  user connects.
- Permission to manage the fleet. Pools appear only on a self-managed instance, and no licence
  gates them there.

## Turn on the fleet

<Steps>
<Step>

### Set the fleet keys

Add to `/opt/alethia/.env`, then restart the console:

| Key | Default | What it does |
| --- | --- | --- |
| `FLEET_PROVIDER` | `manual` | `hcloud` turns the fleet on. `manual` turns it off. |
| `HCLOUD_TOKEN` | none | The fleet project's API token. Required. |
| `ALETHIA_WEB_ORIGIN` | `NEXT_PUBLIC_APP_URL` | The address the VMs call back to. |
| `HCLOUD_SSH_KEYS` | none | Hetzner SSH key IDs, comma-separated, for emergency access. |
| `HCLOUD_SERVER_TYPES` | `cax21,cpx31` | Server types to try, in order. |
| `HCLOUD_IMAGE` | `ubuntu-24.04` | The VM's operating system image. |
| `FLEET_RUNNER_IMAGE_TAG` | `latest` | The runner image tag the VMs pull. |
| `FLEET_RUNNER_SLOTS` | `1` | Jobs one VM runs at the same time. |
| `FLEET_MAX_TOTAL_INSTANCES` | none | A ceiling on VMs across all pools. |
| `FLEET_BOOT_GRACE_SECONDS` | `180` | How long a new VM is safe from scale-down. |

</Step>
<Step>

### Check the runner images

Each cloud you offer needs its runner image at the tag you set:

```bash
for c in aws gcp azure hetzner; do
  docker manifest inspect ghcr.io/alethialabs-io/runner-$c:latest >/dev/null && echo "runner-$c OK"
done
```

</Step>
<Step>

### Create one pool per cloud

Open **Runners** in the console and select **Add pool**. Choose the cloud, the number of VMs to keep
warm, the maximum, and the Hetzner locations. The scaler reads pools on every pass, so no restart is
needed. A paused pool gets no new VMs.

</Step>
</Steps>

## Check that it worked

For each cloud you offer:

1. Connect a test account, and create a project with a small cluster.
2. Run a plan. A server named `fleet-<cloud>-…` appears in the fleet's Hetzner project, and shows in
   **Runners** as online. The plan finishes with its verification result.
3. Deploy, then destroy. The destroy also deletes the job's OpenTofu state.

## If something fails

| Symptom | Cause and fix |
| --- | --- |
| The VM boots and never registers | Its registration token expired during a slow image pull. Raise `FLEET_BOOTSTRAP_TOKEN_TTL_SECONDS` (default `3600`) or `FLEET_BOOT_GRACE_SECONDS`. After 5 failed boots in 30 minutes, the pool pauses itself. |
| The VM cannot pull `runner-<cloud>` | The tag is not published for that cloud. Repeat the image check. |
| The plan fails to sign in to the cloud | The user's setup is missing, or the issuer is not reachable. See [Keyless cloud connectors](/self-host/managed-cloud-connectors#check-that-the-issuer-is-reachable). |
| No VM is created | `FLEET_PROVIDER` is not `hcloud`, `HCLOUD_TOKEN` is empty, or the pool is paused or at its maximum. |
