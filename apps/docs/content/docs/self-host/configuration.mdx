Configure a self-hosted instance by editing `/opt/alethia/.env`, then applying the change. The
installer has already set the domain and generated every instance secret. Compose wires the
internal service addresses, so you do not set those.

To apply a change, recreate the services from `/opt/alethia`:

```bash
docker compose -f docker-compose.yml -f deploy/selfhost/docker-compose.selfhost.yml up -d
```

## Domain and client IP

| Key | What it does |
| --- | --- |
| `ALETHIA_DOMAIN` | The domain Caddy gets a TLS certificate for. Empty: plain HTTP on port 80. |
| `ALETHIA_ACME_EMAIL` | The contact address for Let's Encrypt. |
| `NEXT_PUBLIC_APP_URL`, `BETTER_AUTH_URL` | The public origin, for example `https://alethia.example.com`. Set both when the domain changes. |
| `ALETHIA_TRUSTED_IP_HEADER` | The header that carries the client's IP address. Default: `cf-connecting-ip`. |

The console counts sign-in attempts per client IP, and reads that IP from one header. The bundled
Caddy overwrites `cf-connecting-ip` with the real client address, so the default is correct. If you
put another proxy in front of the app, set `ALETHIA_TRUSTED_IP_HEADER` to a single-value header that
the proxy overwrites, and keep the app unreachable except through it. In production, sign-in answers
`503` when the header is missing or does not hold one valid IP address.

## Sign-in providers

Email sign-in always works. Each OAuth provider you configure adds a button to the sign-in page.

| Provider | Keys | Callback URL to register |
| --- | --- | --- |
| GitHub | `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | `https://<domain>/api/auth/callback/github` |
| Google | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | `https://<domain>/api/auth/callback/google` |
| GitLab | `GITLAB_APPLICATION_ID`, `GITLAB_SECRET` | `https://<domain>/api/auth/oauth2/callback/gitlab` |
| Bitbucket | `BITBUCKET_KEY`, `BITBUCKET_SECRET` | `https://<domain>/api/auth/oauth2/callback/bitbucket` |

To send sign-in codes by email, see [Email](/self-host/email).

## Database and object store

The Compose bundle always uses its own Postgres and SeaweedFS. Compose sets their addresses, and a
value in `.env` does not override them. To use a managed Postgres, or S3 or R2, install with the
[Helm chart](/self-host/helm#use-a-managed-database-or-object-store).

## Other optional keys

| Key | What it turns on |
| --- | --- |
| `ANTHROPIC_API_KEY`, `OPENAI_API_KEY` or `AI_GATEWAY_API_KEY` | The assistant. |
| `INFRACOST_API_KEY` | Cost estimates. |
| `HCLOUD_TOKEN`, `DIGITALOCEAN_ACCESS_TOKEN`, `CIVO_TOKEN` | Token clouds for the bundled runner. |
| `NEXT_PUBLIC_CONNECTOR_ASSETS_ORIGIN` | Serves the connector setup scripts from another public origin. Default: your console. |
| `ALETHIA_LICENSE_KEY` | Enterprise. See [Enterprise setup](/self-host/enterprise-setup). |

`.env.example` in the repository lists every key, with a comment for each.

## Instance secrets

The installer generates 13 instance secrets. `deploy/selfhost/secrets.manifest` lists them with the
command that makes each one. You never type them:

- A first install generates all of them. A later run adds any that are missing and never changes one
  that is set.
- Compose refuses to start when one is empty, and names it. The `preflight` service refuses a
  template placeholder.

Back up `.env`. Without `ALETHIA_CRED_ENCRYPTION_KEY`, the connector secrets and alert-channel
webhooks stored in the database cannot be decrypted.

### Rotate a secret

```bash
sh /opt/alethia/deploy/selfhost/rotate-secret.sh ALETHIA_CRON_SECRET
```

The script writes a new value to `.env` and restarts the services that read it. `--list` prints
every name. Some secrets need more, and the script does it:

| Secret | What else the script does |
| --- | --- |
| `ALETHIA_CRED_ENCRYPTION_KEY` | Keeps the old key as `ALETHIA_CRED_ENCRYPTION_KEY_<id>` and re-encrypts every stored secret with the new one, with no downtime. Delete the old key from `.env` after you check your connectors. |
| `ALETHIA_OIDC_SIGNING_KEY` | Keeps the old key as `ALETHIA_OIDC_SIGNING_KEY_PREVIOUS`, so tokens it signed still verify. Delete that key after 24 hours. |
| Database passwords | Changes the role's password in Postgres first, then writes `.env`. |
| Storage keys | Recreates the object store with the new identity. |

For any other secret, sessions and tokens signed with the old value stop being accepted. Rotating
`BETTER_AUTH_SECRET` signs everyone out.
