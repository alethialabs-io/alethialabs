<Enterprise />

Turn a self-hosted instance from <Community>Community</Community> into
<Enterprise>Enterprise</Enterprise>. The published console image already contains the Enterprise
code. A licence key turns it on. What each edition includes is in the
[feature matrix](/editions/feature-matrix).

## Before you begin

- A self-hosted instance running the published images. See [Install on a VM](/self-host/install).
- A licence key from Alethia Labs. It is a signed token.

## Activate the licence

<Steps>
<Step>

### Add the key

Set the key in `/opt/alethia/.env`:

```bash
ALETHIA_LICENSE_KEY=<the licence you were issued>
```

</Step>
<Step>

### Restart the console

From `/opt/alethia`:

```bash
docker compose -f docker-compose.yml -f deploy/selfhost/docker-compose.selfhost.yml up -d app
```

The console checks the licence's signature offline, against keys built into the image. It sends
nothing to Alethia Labs.

</Step>
</Steps>

The database tables for organizations, teams and SSO are already there: the `migrate` service
applies every migration on each start.

## Optional: use OpenFGA

Enterprise runs on the built-in Postgres authorization engine. To use the
[OpenFGA engine](/concepts/access-control/openfga) instead:

1. Start it:

   ```bash
   docker compose -f docker-compose.yml -f deploy/selfhost/docker-compose.selfhost.yml --profile enterprise up -d openfga
   ```

2. Create a store, and note the `id` in the answer:

   ```bash
   curl -X POST http://localhost:8082/stores -H 'content-type: application/json' -d '{"name":"alethia"}'
   ```

3. Set `OPENFGA_API_URL=http://openfga:8080` and `OPENFGA_STORE_ID=<id>` in `.env`, and restart the
   console as above.

On start, the console writes the authorization model and copies your existing grants into OpenFGA.
With either key empty, the Postgres engine stays in use.

## Optional: register an SSO provider

In **Settings → Single Sign-On**, register your identity provider over
[OIDC or SAML](/guides/access/sso).

## Check that it worked

- The organization switcher and **Settings → Members**, **Teams** and **Roles** are available.
- Invite a second member, and accept the invitation. See
  [Members and invitations](/guides/access/members-and-invitations).
- In **Settings → Access**, grant a role and add a deny exception, then check that it applies. See
  [Grants and scopes](/guides/access/grants-and-scopes).

If none of this appears, the licence did not verify. A licence that is missing, expired, or signed by
another key grants nothing, and the console runs as Community. The console still starts.

## What happens when the licence ends

A licence keeps working for a grace period after its end date: 30 days, unless the licence states
another period. No restart is needed for either change. After the grace period, the instance goes
back to Community behaviour. No data is deleted. Members already in an
organization keep their data, and Enterprise-only operations stop until a valid licence is set.
