---
title: Scaling out
description: Run several console replicas of a self-hosted Alethia behind one ingress, with no message broker.
---

Run more than one console container, for throughput or so that one restart does not take the
console down. The replicas need nothing beyond the bundled Postgres.

## Before you begin

- A working install. See [Install on a VM](/self-host/install).
- Memory for each extra replica. The Helm chart requests 512 MiB for each; give it more under load.

## Add replicas

From `/opt/alethia`:

```bash
docker compose -f docker-compose.yml -f deploy/selfhost/docker-compose.selfhost.yml up -d --scale app=3
```

Caddy sends requests to every `app` container. On the Helm chart, set `console.replicas` instead.

## Why no broker is needed

- **Live updates.** Job logs, support messages and runner wake-ups reach the browser over
  Server-Sent Events. Each replica listens to Postgres `LISTEN`/`NOTIFY` itself, so an event written
  through any replica reaches the browsers connected to every replica.
- **Rate limits.** The counters are in Postgres, so all replicas count against the same limit, and a
  restart does not reset them.
- **Stored state.** Every replica uses the same database and object store.

The compose file also defines a `redis` service in the `scale-out` profile. Nothing in the current
release uses it, so do not start it.

## Check that it worked

```bash
docker compose -f docker-compose.yml -f deploy/selfhost/docker-compose.selfhost.yml ps app
```

Three `app` containers are `running`. Open a job's log in two browsers: both show new lines as the
job writes them.
