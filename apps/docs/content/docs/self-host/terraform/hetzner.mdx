Provision a Hetzner Cloud server for the control plane with `infra/cp-hetzner`. Web traffic comes
through a Cloudflare Tunnel, and the firewall allows only SSH. Read
[OpenTofu per cloud](/self-host/terraform) first.

<Callout type="warn">
  This stack is also the one the hosted service runs on. It imports the hosted service's own DNS
  record (`dns-imports.tf`) and carries its email routing, switched off. Remove `dns-imports.tf`
  before you apply it to your zone, or the plan fails.
</Callout>

## What it creates

- A `cx33` server (x86, 4 vCPU, 8 GB) and a 25 GB volume. Docker's data, so Postgres and the object
  store, live on the volume.
- Delete and rebuild protection on the server and the volume, and `prevent_destroy` in OpenTofu.
- A firewall that allows only SSH (port 22).
- The Cloudflare Tunnel, and proxied CNAME records for the apex and `www`.

At Hetzner's list price this costs about €14 a month: the server €13.10 and the volume €1.19.

## Before you begin

- A Hetzner Cloud project and an API token for it.
- An SSH public key. SSH is the admin channel on Hetzner.
- The Cloudflare token, zone ID and account ID.

## Apply

```bash
cd infra/cp-hetzner
cp backend.hcl.example backend.hcl
cp terraform.tfvars.example terraform.tfvars   # hcloud_token, cloudflare_*, ssh_public_key, domain
tofu init -backend-config=backend.hcl
tofu plan -out=tfplan
tofu apply tfplan
```

Variables you may change: `server_type` (`cx43` for a busier instance), `data_volume_size`,
`location` (default `fsn1`), `ssh_allowed_cidrs`.

To remove the server later, first apply a change that turns the protections off, then destroy. See
`infra/cp-hetzner/README.md`.

## Check that it worked

```bash
ssh root@<server ip> ls /opt/alethia
```
