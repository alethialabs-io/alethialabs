title: OpenTofu per cloud
description: Provision a hardened control-plane VM and a Cloudflare Tunnel on Hetzner, AWS, GCP or Azure with OpenTofu, with no open web ports.
---

Provision the VM for a self-hosted instance as code. Each cloud has an OpenTofu stack in
`infra/cp-<cloud>/` that creates one x86 VM with no open web port, and a Cloudflare Tunnel that
carries its traffic.

<Callout type="warn">
  These stacks prepare the VM: Docker, a clone of the repository in `/opt/alethia`, and the tunnel.
  They do not start Alethia, and the self-host bundle does not include the tunnel's connector
  (`cloudflared`). Use them only if you will run `cloudflared` on the VM yourself. Otherwise use the
  [installer](/self-host/install) or the [one-click templates](/self-host/one-click), which serve
  HTTPS directly.
</Callout>

## Choose a cloud

Apply one stack per domain. Two stacks on the same domain fight over its DNS records and tunnel.

| Cloud | Stack | Default VM | Admin access | Page |
| --- | --- | --- | --- | --- |
| Hetzner | `infra/cp-hetzner` | `cx33`, 4 vCPU, 8 GB | SSH with a key | [Hetzner](/self-host/terraform/hetzner) |
| AWS | `infra/cp-aws` | `t3.large`, 2 vCPU, 8 GB | SSM Session Manager | [AWS](/self-host/terraform/aws) |
| GCP | `infra/cp-gcp` | `e2-standard-2`, 2 vCPU, 8 GB | SSH through IAP | [GCP](/self-host/terraform/gcp) |
| Azure | `infra/cp-azure` | `Standard_D2s_v5`, 2 vCPU, 8 GB | `az vm run-command` and Serial Console | [Azure](/self-host/terraform/azure) |

Every VM is x86, because the images are `linux/amd64` only.

## What every stack does

- **No inbound web traffic.** The firewall opens no port 80 or 443. `cloudflared` on the VM dials out
  to Cloudflare, and TLS ends at Cloudflare's edge.
- **Proxied DNS.** The apex and `www` are proxied CNAME records onto `<tunnel id>.cfargotunnel.com`.
  The tunnel sends both to `http://caddy:80` on the VM.
- **Checks in the plan.** Each stack's `checks.tf` fails the plan if the posture regresses, for
  example if a web port opens.

## Before you begin

- A Cloudflare zone, its zone ID and account ID, and an API token with DNS edit and Cloudflare Tunnel
  permissions.
- An S3-compatible bucket for OpenTofu state.
- Credentials for the cloud. Use short-lived ones, such as the cloud CLI's sign-in.
- OpenTofu.

## Apply a stack

```bash
cd infra/cp-<cloud>
cp backend.hcl.example backend.hcl            # the state bucket's endpoint and credentials
cp terraform.tfvars.example terraform.tfvars  # domain, cloudflare_* IDs, cloud settings
tofu init -backend-config=backend.hcl
tofu plan -out=tfplan
tofu apply tfplan
```

Read the plan before you apply it. Then get the tunnel's token, which `cloudflared` needs:

```bash
tofu output -raw tunnel_token
```

The token is a secret. Pass it to `cloudflared` as `TUNNEL_TOKEN`; do not print it into logs.

## Check that it worked

The cloud console shows one VM named `alethia-cp`. In Cloudflare, the tunnel exists and the apex
record points at it. The tunnel shows as healthy once `cloudflared` runs on the VM.
