Make a self-hosted console send email. Until you do, it writes sign-in codes and every other email
to its log, so a new install works without email.

## Before you begin

- A domain whose DNS you control.
- Either an SMTP service (Postmark, Mailgun, SES SMTP, or Mailpit for testing), or an AWS account
  with SES production access. A new SES account is in the sandbox and can mail only verified
  addresses.

## Choose the sending addresses

Send each kind of mail from its own subdomain, so a spam complaint about one kind does not stop
sign-in codes from arriving. Your root domain keeps your own mailboxes and sends no app email.

| Mail | Subdomain | Key | Example |
| --- | --- | --- | --- |
| Sign-in codes, verification | `auth.` | `AUTH_EMAIL_FROM` | `Alethia <no-reply@auth.example.com>` |
| Invitations, job notifications | `mail.` | `EMAIL_FROM` | `Alethia <hello@mail.example.com>` |

`EMAIL_FROM` falls back to `AUTH_EMAIL_FROM` when it is not set. Quote both values in `.env`.

## Send through SMTP

1. Verify both subdomains with your SMTP provider. It gives you the SPF and DKIM records to add.
2. Set these keys in `/opt/alethia/.env`:

   | Key | What it does |
   | --- | --- |
   | `SMTP_HOST` | The server. Setting it selects SMTP. |
   | `SMTP_PORT` | Default `587`. |
   | `SMTP_USER`, `SMTP_PASS` | Credentials, if the server needs them. |
   | `SMTP_SECURE` | TLS from the first byte. Default: `true` on port 465, otherwise `false`. |
   | `AUTH_EMAIL_FROM`, `EMAIL_FROM` | The addresses above. |

3. Apply the change: run `docker compose -f docker-compose.yml -f deploy/selfhost/docker-compose.selfhost.yml up -d`
   from `/opt/alethia`.

## Send through AWS SES

1. In the SES console, in one region, create a domain identity for `auth.example.com` and for
   `mail.example.com`.
2. Turn on Easy DKIM for each identity, and add the three CNAME records SES shows.
3. Set a custom MAIL FROM domain for each (for example `bounce.auth.example.com`), and add the MX and
   SPF records below.
4. Request production access.
5. Give the console permission to send: an IAM role on the VM with `ses:SendEmail` and
   `ses:SendRawEmail`, or an IAM user with those permissions and its keys in `.env`.
6. Set the keys and apply the change as in the SMTP steps:

   ```bash
   ALETHIA_SES_REGION=eu-west-1
   ALETHIA_SES_ACCESS_KEY_ID=...        # only without an IAM role
   ALETHIA_SES_SECRET_ACCESS_KEY=...    # only without an IAM role
   AUTH_EMAIL_FROM="Alethia <no-reply@auth.example.com>"
   EMAIL_FROM="Alethia <hello@mail.example.com>"
   ```

Setting `ALETHIA_SES_REGION` selects SES. `AWS_REGION` selects it too when `ALETHIA_SES_REGION` is
not set.

### DNS records for SES

| Record | Host | Type | Value |
| --- | --- | --- | --- |
| DKIM, three of them | `<token>._domainkey.<subdomain>` | CNAME | `<token>.dkim.amazonses.com` |
| MAIL FROM | `bounce.<subdomain>` | MX | `10 feedback-smtp.<region>.amazonses.com` |
| MAIL FROM SPF | `bounce.<subdomain>` | TXT | `v=spf1 include:amazonses.com ~all` |
| DMARC, once | `_dmarc.example.com` | TXT | `v=DMARC1; p=none; rua=mailto:dmarc@example.com` |

Start DMARC at `p=none`. Move to `p=quarantine`, then `p=reject`, once the reports are clean.

### Stop mailing addresses that bounce

Optional. SES can report bounces and complaints, so the console stops mailing those addresses:

1. Create an SES configuration set for each kind of mail, and set `ALETHIA_SES_AUTH_CONFIG_SET` and
   `ALETHIA_SES_GENERAL_CONFIG_SET`.
2. Publish `Bounce` and `Complaint` events from both to one SNS topic.
3. Set `ALETHIA_SES_EVENTS_TOPIC_ARNS` to the topic's full ARN (comma-separated for more than one).
   Do this before the next step: without it, the console refuses every message with `503`.
4. Subscribe `https://<domain>/api/webhooks/ses` to the topic over HTTPS.

A permanent bounce or a complaint puts the address on a suppression list, and later sends skip it.
The OpenTofu stack in `infra/email-ses/` creates all of the SES pieces on this page; read its
`README.md` before you apply it to your domain.

## Which transport is used

`EMAIL_PROVIDER` (`smtp` or `ses`) chooses the transport. Without it, SMTP wins when `SMTP_HOST` is
set, then SES. Any other value stops the console with an error. `EMAIL_PROVIDER=resend`, or a
`RESEND_API_KEY` with nothing else set, is also an error: Resend support was removed.

## Check that it worked

Request a sign-in code from the console. It arrives from your `auth.` address; check the spam folder
on the first send. If it does not arrive, read the console's log: it shows the SMTP or SES error, or
the line `[email] no provider configured` when no transport is set.
