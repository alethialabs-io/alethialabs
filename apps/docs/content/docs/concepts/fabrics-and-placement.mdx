An **environment** is where you deliver your apps; a **Fabric** is the infrastructure that hosts it:
a cluster, its network, shared add-ons and its own OpenTofu state. A **placement** says how an
environment sits on a Fabric, so several environments can share one cluster.

## How it works

A project owns one or more Fabrics. A Fabric can come from an Alethia template or from
[your own OpenTofu module](/concepts/bring-your-own-iac). Each environment names the Fabric it is
placed on and its placement mode. A Fabric has at most one cluster, and every environment placed on
it shares that cluster.

### Placement modes

The modes form an isolation ladder. Each step isolates more and costs more.

| Mode | What the environment gets | Isolation |
| --- | --- | --- |
| `namespace` | A Kubernetes namespace on a shared cluster. | Soft. Same nodes and API server as its neighbors, bounded by `ResourceQuota`, `LimitRange`, `NetworkPolicy` and Pod Security Admission. |
| `vcluster` | A virtual cluster on a shared cluster: its own API server, custom resources and Kubernetes version. | Medium. Its own control plane, but its pods run on the shared nodes. |
| `dedicated` | A whole cluster: the environment owns its Fabric. | Hard. A separate cluster. |

`dedicated` is the default for a new project's first environment. An empty mode is treated as
`dedicated`. All three modes work on AWS, GCP, Azure and Hetzner. A deploy that cannot honor the
placement you chose fails; it never ignores the placement.

<Callout type="warn">
  A `vcluster` isolates the control plane, not the nodes. Do not use it as a boundary for untrusted
  workloads. Use `dedicated` for that, and `namespace` for targets of the same trust, such as `dev`
  and previews.
</Callout>

### What each side tracks

- **Infrastructure is per Fabric.** Each Fabric has its own [OpenTofu state](/concepts/terraform-state),
  and [drift detection](/concepts/drift) runs per Fabric.
- **Delivery is per environment.** ArgoCD syncs each environment's apps into its own destination: the
  namespace for `namespace` and `vcluster`, the whole cluster for `dedicated`. See
  [GitOps and ArgoCD](/concepts/gitops-argocd).
- **Managed data is per environment.** A database belongs to the environment that declares it, also on
  a shared Fabric.

A `dedicated` environment is the simple case: infrastructure and delivery are the same cluster.

## What it does not do

- It does not give a kubeconfig for a `namespace` or `vcluster` environment. A kubeconfig for the
  shared cluster would reach every environment on it, so the runner refuses. See
  [Cluster access](/concepts/cluster-access).
- It does not make a `vcluster` a hard boundary.
