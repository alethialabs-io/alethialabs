Bring-your-own IaC (BYO IaC) points an environment at a Git repository that holds your own OpenTofu
root module, and Alethia provisions the environment from it instead of its built-in template. Your
module is arbitrary code, so Alethia vets it with a static safety gate and runs only the exact commit
it vetted.

To attach, scan and detach a module, see [Bring your own IaC](/guides/design-project/bring-your-own-iac).

## How it works

### Replace, not compose

A module provisions the environment instead of the template, not next to it. An environment has at
most one module. Attaching is refused while the environment has template-provisioned infrastructure
deployed or in progress; destroy it first.

The feature is off unless the operator sets `ALETHIA_BYO_IAC_ENABLED=true`. While it is off, attach,
scan and provisioning all refuse.

### Lifecycle

1. **Attach** a repository, ref and module path to an environment, with optional variable values and
   a Git credential.
2. **Scan.** An `IAC_SCAN` job clones the repository, pins the commit it checked out, lists the
   providers and modules, runs the safety gate and `tofu validate`. Provisioning stays locked until a
   clean scan pins a commit.
3. **Plan and deploy** the pinned commit, never the moving ref. The gate runs again, the backend is
   replaced with the state proxy, and the plan goes through the same [Elench](/concepts/elench) check
   as a template plan. A successful deploy records its commit.
4. **Detect drift** on the pinned commit, as for any environment. See [Drift detection](/concepts/drift).
5. **Destroy** runs the last deployed commit, then removes the state. A source that never deployed can
   be detached at any time; one with live infrastructure must be destroyed first.

A ref that moves after the scan cannot bring unvetted code into an apply: a deploy needs a pinned
commit.

### The safety gate

The gate parses the root module and every local child module. It never evaluates expressions, never
runs `tofu` and never fetches remote code. Any error-level finding fails the job before `tofu` runs.
It runs at scan time and again on every plan, deploy and destroy.

| Finding | Level | Why |
| --- | --- | --- |
| A provider not on the allowlist | Error | `tofu init` downloads and runs provider binaries. Covers declared providers and providers implied by a resource type. |
| A `provisioner` block | Error | `local-exec` and `remote-exec` run commands at apply. |
| `data "external"` | Error | Runs a program during plan. |
| A remote or absolute module source | Error | Code the gate never saw would be fetched and run. Only `./` and `../` sources pass. |
| A module or symlink that leaves the repository | Error | The gate cannot vouch for it. |
| An override file (`override.tf`, `*_override.tf` and the `.tofu` and JSON forms) | Error | It could replace the platform's backend and move state to local disk. |
| A file that does not parse | Error | What the gate cannot read, it cannot vouch for. |
| `data "http"` | Warning | Network access during plan. |
| `data "terraform_remote_state"` | Warning | Reads other state during plan. |
| A `backend` or `cloud` block | Warning | Ignored: Alethia replaces it. |

The default allowlist includes the AWS, Google (`google`, `google-beta`), Azure (`azurerm`,
`azuread`) and Hetzner Cloud providers, and `kubernetes`, `helm`, `tls`, `random`, `time`,
`cloudinit`, `dns`, `local`, `null` and `template` from `hashicorp/`. A provider from any other
registry host never matches. The operator can replace the list with
`ALETHIA_BYO_IAC_PROVIDER_ALLOWLIST`.

### Variables Alethia passes

Alethia sets these as `TF_VAR_*` environment variables. The names never change or disappear; new ones
may be added. Declare the ones you use:

| Variable | Value |
| --- | --- |
| `alethia_project` | The project name. |
| `alethia_environment` | The environment stage, such as `production`. |
| `alethia_region` | The primary region. |
| `alethia_project_id` | The project's ID. |
| `alethia_environment_id` | The environment's ID. |

Your own variable values are passed as a variable file. A key that starts with `alethia_` is dropped
with a warning, so it cannot replace a platform value. Only strings, numbers and booleans pass;
objects and lists are dropped with a warning, and `null` leaves your module's default.

### State

Alethia writes its own `http` backend into the clone and binds it to the per-job
[state proxy](/concepts/terraform-state). Your `backend` block is ignored. The runner holds no storage
credential, and the job's token reaches only that environment's state.

### Cluster setup from your outputs

If your module outputs a cluster, Alethia sets it up like a template cluster: reachability check,
ArgoCD and add-ons. If it outputs none, Alethia provisions it, records the outputs, and stops there.

| Output | Purpose |
| --- | --- |
| `cluster_name` | Turns on cluster setup. Empty means no cluster. |
| `cluster_endpoint` | The API server URL. |
| `cluster_ca_certificate` | The base64 CA certificate. |
| `kubeconfig` | A complete kubeconfig, used as is. For a self-managed cluster. |

For EKS, GKE or AKS, output the first three; the runner builds a kubeconfig that mints its own
short-lived tokens. For a cluster you hold the PKI for, such as Talos, output `kubeconfig`.

<Callout type="warn">
  Use these exact names. An output named differently, such as `k8s_cluster`, reads back empty: the
  deploy succeeds, and Alethia silently skips the kubeconfig, ArgoCD and every add-on.
</Callout>

Your module must also make the runner's identity a cluster admin, because ArgoCD is installed with
that identity. Without it the install is refused and the deploy fails at the GitOps step.

| Cloud | Grant the runner's identity cluster admin with |
| --- | --- |
| AWS | An `aws_eks_access_entry` and an `aws_eks_access_policy_association` with `AmazonEKSClusterAdminPolicy`. |
| GCP | `roles/container.admin` or `roles/container.clusterAdmin` for the runner's service account. |
| Azure | An `azurerm_role_assignment` of Azure Kubernetes Service RBAC Cluster Admin, or the runner's group in `admin_group_object_ids`. |
| Talos or self-managed | An admin `kubeconfig` output. |

### Who can run it

- **Self-operated runners** run BYO IaC inside your own cloud account and trust boundary. This is
  available when the feature flag is on.
- **Managed runners** refuse BYO IaC unless the per-job container sandbox with enforced egress is on
  (`ALETHIA_SANDBOX_BACKEND=container`, `ALETHIA_SANDBOX_EGRESS_ENFORCED` and
  `ALETHIA_SANDBOX_ENFORCE_MANAGED`). See [Isolated execution](/concepts/isolated-execution).

## What it does not do

- It does not combine your module with an Alethia template.
- It does not run a ref that was not scanned and pinned.
- It does not fetch remote modules or unlisted providers.
- It does not grant the runner cluster admin for you.
- The evidence receipt does not record the commit. The scanned and deployed commits are recorded on
  the environment's source.
