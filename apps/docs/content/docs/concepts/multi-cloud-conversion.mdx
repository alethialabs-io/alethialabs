When you duplicate a project and pick a cloud identity on another cloud, Alethia converts the design
for you. It maps each setting to the target cloud, clears what cannot carry over, and lists a warning
for each change so you can review it before you submit.

## How it works

1. Select **Duplicate & Edit** on a project.
2. Choose a cloud identity on another cloud.
3. Alethia converts the design and shows the warnings.
4. Review and change the draft, then submit it.

### What is mapped

| Setting | What happens |
| --- | --- |
| Region | Mapped to the nearest region on the target, for example AWS `us-east-1` → GCP `us-east4` → Azure `eastus`. With no match, the target's default region, with a warning. |
| Machine types | Mapped to an equivalent, for example `t3.medium` → `e2-standard-2` → `Standard_B2s`. A mapping never picks a type too small to run the cluster add-ons, so it can pick a larger node. With no match, the target's default type, with a warning. |
| Kubernetes version | Set to the target's default version. |
| Autoscaler | Replaced with the target's equivalent, for example Karpenter → GKE Autopilot → the AKS cluster autoscaler. |
| Spot capacity | Kept where the target sells Spot. On Hetzner, or on GKE Autopilot, the cluster uses on-demand nodes, with a warning. On Azure, Spot adds a separate Spot pool; the system pool stays on-demand. |
| Database engine | Mapped, for example `aurora-postgresql` → `cloudsql-postgresql` → `azure-postgresql`. An engine the target does not offer switches, with a warning: MySQL on Hetzner becomes PostgreSQL. |
| Database capacity | Kept inside the target's range. The unit changes: Aurora capacity units on AWS, vCPUs on GCP, vCores on Azure. A warning names the new unit. |
| Cache | The node type is mapped, or set to the target's default. A Valkey cache moved to Azure becomes Redis. |
| NoSQL tables | Converted with a note on the data-model difference. A capacity mode the target does not offer, or a range key it does not support, is changed or dropped, with a warning. |
| Network CIDR | Kept. |

### What is cleared

These identify resources in the source account, so they cannot carry over. Set them again on the
target.

- An existing network you reused. The draft provisions a new network instead.
- The DNS zone and domain. Select a zone in the target account.
- WAF rules. The rule formats differ between clouds.
- IAM roles, service accounts and cluster admin identities.

## What it does not do

- It does not move data. A converted project provisions new, empty resources.
- It does not submit for you. The converted design is a draft until you submit it.
- It does not offer a component the target cannot build. See
  [Cloud abstraction](/concepts/cloud-abstraction).
