After a successful apply, the runner installs ArgoCD in the new cluster and hands it the cluster
services and your apps repository. From then on, Git is the source of truth: ArgoCD keeps the cluster
in sync with the repository.

## How it works

1. The runner reads the OpenTofu outputs: cluster name, endpoint and certificate, DNS zone, database
   and cache endpoints, and the cloud identities made for in-cluster controllers.
2. It writes a kubeconfig whose credential plugin is the runner itself. Each `kubectl` or Helm call
   mints a short-lived token from the job's keyless cloud credential. No cloud CLI is used and no
   long-lived kubeconfig is stored.
3. It installs ArgoCD with Helm and waits for its pods to be ready.
4. It renders the outputs into a values file, the *infrastructure facts*, and applies the platform
   Applications that use them.
5. It creates an `apps` Application that syncs your apps repository, at the environment's apps path or
   the repository root.
6. It records the ArgoCD address and cluster details on the environment. Passwords, kubeconfigs and
   generated secret values are never stored.

The ArgoCD admin password stays in the cluster, in the `argocd-initial-admin-secret` Secret. Read it
with admin [cluster access](/concepts/cluster-access):

```bash
kubectl -n argocd get secret argocd-initial-admin-secret \
  -o jsonpath='{.data.password}' | base64 -d
```

### Platform services

Each service is an ArgoCD Application. A service that does not apply to a cloud renders nothing and is
skipped, and the console records why. The per-cloud result is in
[Cloud abstraction](/concepts/cloud-abstraction#cluster-services-after-the-apply).

| Service | What it does | Where |
| --- | --- | --- |
| external-dns | Creates DNS records from your Ingress objects. | Every cloud, when DNS is on with a domain and its identity or token exists. Uses Route 53, Cloud DNS, Azure DNS, Hetzner DNS, or Cloudflare when that connector is attached. |
| External Secrets Operator | Syncs secrets from the cloud's secret store into Kubernetes Secrets. | Every cloud. |
| cert-manager | Issues certificates through a DNS challenge, and provides webhook certificates for add-ons that need them. | Issuing on AWS, GCP and Azure with the cloud's own DNS. Webhook certificates on every cloud. |
| AWS Load Balancer Controller | Turns Ingress objects into ALBs. | AWS. |
| Application Gateway Ingress Controller | Turns Ingress objects into rules on one Application Gateway. | Azure, when the gateway is on. |
| Karpenter | Launches nodes for pending pods. | AWS, when enabled. |
| metrics-server | CPU and memory metrics for autoscaling and `kubectl top`. | AWS and Hetzner. GKE and AKS ship their own. |
| gp3 storage class | The default EBS storage class. | AWS. |

### Keyless identities for controllers

Controllers that call the cloud use a workload identity, never a static key:

| Cloud | Identity | Bound with |
| --- | --- | --- |
| AWS | IAM role for the service account (IRSA) | `eks.amazonaws.com/role-arn` annotation |
| GCP | Google service account through GKE Workload Identity | `iam.gke.io/gcp-service-account` annotation |
| Azure | User-assigned managed identity with a federated credential on the AKS OIDC issuer | `azure.workload.identity/client-id` annotation |

On Hetzner, external-dns and the cloud controller use the connected Hetzner API token, which is
stored in the cluster as a Secret.

### Your apps

The `apps` Application syncs your apps repository with automatic sync, prune and self-heal. If the
repository is empty, the runner first commits generated manifests for your detected services: a
Deployment, Service and Ingress each, running as non-root with a read-only root file system and
resource limits. A repository that already has manifests is never changed.

Marketplace add-ons and [your own charts](/concepts/bring-your-own-charts) are Applications too, each
in its own ArgoCD project.

## What it does not do

- It does not extract or store the ArgoCD admin password.
- It does not overwrite your apps repository.
- It does not install an ingress controller on GCP, Azure (without the gateway) or Hetzner. Install
  the Traefik add-on there.
- It does not expose the ArgoCD UI outside AWS. Elsewhere, port-forward to it.
