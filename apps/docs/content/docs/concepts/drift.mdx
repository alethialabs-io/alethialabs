Provisioning proves an environment matched its design at the moment of the apply. Drift detection
keeps checking: on a schedule, a runner compares each environment's OpenTofu state with the live
cloud and records whether anything changed.

## How it works

### Schedule

A loop in the control plane queues a `DETECT_DRIFT` job for each environment whose last check is
older than its cadence:

| Stage | Cadence |
| --- | --- |
| Production | Every 6 hours |
| Staging | Every day |
| Development | Every 7 days |

An environment never checked is due at once. An environment with a drift job already queued or
running is skipped, so checks do not pile up. To check one environment now, open the canvas **Run**
menu and select **Detect drift**.

### The check

The job copies the configuration of the environment's latest successful deploy. The runner prepares
the template (or clones your [bring-your-own module](/concepts/bring-your-own-iac) at its pinned
commit), reads the state through the [state proxy](/concepts/terraform-state), and runs
`tofu plan -refresh-only`. This asks each provider what the live resource looks like and compares it
with the state. It never applies and changes nothing in the cloud.

A refresh-only plan still runs provider plugins. For a bring-your-own module on a managed runner, the
job runs only inside the [container sandbox](/concepts/isolated-execution).

### The posture

Each drifted managed resource is classified:

| Kind | Meaning |
| --- | --- |
| `modified` | It exists, but its live configuration differs from the state. |
| `deleted` | It was deleted outside OpenTofu and is still in the state. |
| `other` | Any other kind of change. |

The posture records whether the environment is in sync, how many resources drifted, each one's
OpenTofu address, type and kind, and when the plan ran. Alethia keeps the latest posture per
environment.

If an environment drifted, Alethia can heal it by deploying again. Auto-heal is off unless you turn it
on, and production stays behind approval.

### What you see

The Evidence page and the **Drift** tab show one mark per environment:

| Mark | Meaning |
| --- | --- |
| **In sync** | The last check found no drifted managed resource. |
| **N drifted** | That many managed resources differ from the state. |
| **Not scanned** | No check has run yet. This is an unknown, not a pass. |

The CLI (`alethia drift`) and the MCP tool `get_drift_posture` read the same posture.

## What it does not do

- It does not see resources OpenTofu does not manage. A resource created outside OpenTofu is not in
  the state, so a refresh-only plan cannot find it. The posture says this: its unmanaged count is
  marked as unknown, never as zero.
- It does not check app delivery. Drift between your apps repository and the cluster is ArgoCD's to
  report.
- It does not change anything, unless you turned on auto-heal.
