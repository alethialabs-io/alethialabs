OpenTofu records the resources it manages in a state file. Alethia keeps one state file per
environment in S3-compatible object storage, and every runner reaches it only through the control
plane's state proxy, so no runner holds a storage credential.

## How it works

For each job, the runner writes an OpenTofu `http` backend that points at the control plane:

```hcl
address        = "{console_url}/api/jobs/{job_id}/state"
lock_address   = "{console_url}/api/jobs/{job_id}/state/lock"
unlock_address = "{console_url}/api/jobs/{job_id}/state/lock"
```

The runner authenticates with a token minted for that job. It passes the token to `tofu` in the
`TF_HTTP_PASSWORD` environment variable and never writes it to the work directory. The control plane
derives the state object's key from the job, so one job's token reaches only its own environment's
state.

The state key is `{project}-{environment}-{region}/tofu.tfstate`. Each environment, not only each
project, has its own state, which is why `staging` and `production` are isolated. With
[Fabrics](/concepts/fabrics-and-placement), state is per Fabric.

The storage behind the proxy is any S3-compatible service: SeaweedFS by default, or Garage, MinIO,
AWS S3 or Cloudflare R2. Its endpoint and credentials are set on the control plane only. See
[Self-host configuration](/self-host/configuration).

### Locking

`tofu` takes a lock through the proxy before it writes. The lock is fenced: a runner whose lock was
taken over cannot overwrite the state written by the new holder.

### State and retries

OpenTofu writes state after each resource it creates, changes or deletes. If a run stops partway, the
state holds everything done so far. The next run reads it and plans only what remains, so nothing is
created twice.

A destroy removes every resource in the state. The state object stays, empty.

### Plan files

A plan job saves its binary plan file with the control plane, in a separate bucket. A deploy downloads
that file and applies it, after checking its SHA-256 against the plan you reviewed. See
[Provisioning pipeline](/concepts/provisioning-pipeline#6-apply).

## What it does not do

- It does not give a runner a storage key. This is what lets untrusted
  [bring-your-own code](/concepts/bring-your-own-iac) run against state safely.
- It does not use the backend your own module declares. Alethia overrides it with the proxy.
- It does not share state between environments.
