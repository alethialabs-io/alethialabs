A runner provisions from OpenTofu templates that ship inside its image, one per cloud. Each template
is plain OpenTofu: a design reaches it only as variables, and its state goes through the control
plane.

## How it works

| Template | Path | What it builds |
| --- | --- | --- |
| [AWS](/concepts/runner/infrastructure-templates/aws) | `infra/templates/project/aws/` | EKS with Karpenter, Aurora, ElastiCache, DynamoDB, SQS and SNS, S3, ECR, WAF and the network. |
| [GCP](/concepts/runner/infrastructure-templates/gcp) | `infra/templates/project/gcp/` | GKE (Standard or Autopilot), Cloud SQL, Memorystore, Firestore, Pub/Sub, Cloud Storage, Artifact Registry, Cloud Armor and the network. |
| [Azure](/concepts/runner/infrastructure-templates/azure) | `infra/templates/project/azure/` | AKS, Azure Database, Azure Managed Redis, Cosmos DB, Service Bus, Storage, ACR, Key Vault, the WAF and Application Gateway, and the network. |
| [Hetzner](/concepts/runner/infrastructure-templates/hetzner) | `infra/templates/project/hetzner/` | A Talos Kubernetes cluster on Hetzner servers, its network, firewall, DNS zone and object storage buckets. |
| Runner | `infra/templates/runner/aws/` | A self-deployed runner on ECS Fargate. See [Job execution](/concepts/runner/job-execution#runner-lifecycle). |
| ArgoCD | `infra/templates/argocd/` | The platform Applications installed after the apply. See [GitOps and ArgoCD](/concepts/gitops-argocd). |

Each per-cloud runner image carries its own template, initialized when the image is built, so a job
downloads no providers or modules.

For each job, the runner writes the environment's [configuration snapshot](/concepts/provisioning-pipeline)
as `terraform.tfvars.json` with the variable names of that cloud's template. The templates declare an
empty `backend "http"` block, which the runner binds to the per-job
[state proxy](/concepts/terraform-state).

### Settings you can change

Most templates accept settings beyond the canvas form, as keys in a component's `provider_config`. In
the console, open the component on the canvas and set them on its template settings card. Settings
are off by default: a project that sets none gets the same infrastructure as before the setting
existed. The cloud pages list them.

The node pool keys `node_labels`, `node_taints` and `extra_node_pools` are the same on every cloud;
their rules are in [Node labels, taints and extra pools](/reference/node-pools).
Every cloud taints arm64 pools with `alethia.io/arch=arm64:NoSchedule`, because the images Alethia
builds are amd64 only, and keeps the default pool untainted for Alethia's add-ons.

## What it does not do

- It does not template the `.tf` files. Values reach them only through variables.
- It does not download providers at job time.
- It does not let you edit the template for one project. To provision from your own code, use
  [bring-your-own IaC](/concepts/bring-your-own-iac).
