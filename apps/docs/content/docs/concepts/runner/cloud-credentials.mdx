A runner gets a cloud credential at the start of every job and removes it when the job ends, even if
the job fails. On AWS, GCP and Azure the credential is keyless: the runner exchanges a short-lived
assertion from Alethia's own OIDC issuer. Hetzner has no federation, so it uses an API token.

## How it works

The runner asks the control plane for an assertion for the job's cloud, writes it to a token file,
and points OpenTofu's provider at that file. The cloud checks the assertion and returns a session of
about an hour. A background refresher writes a new assertion into the file every few minutes, so an
apply longer than one session keeps working. Why the cloud trusts the assertion is explained in
[Security](/concepts/security).

| Cloud | What the connection stores | What the runner does |
| --- | --- | --- |
| AWS | The role ARN | Writes an AWS profile with `web_identity_token_file` and `role_arn`, and points OpenTofu at it with `AWS_CONFIG_FILE` and `AWS_PROFILE`. AWS STS returns the role's session. |
| GCP | The project ID and the Workload Identity Federation configuration: pool, provider, service account | Points the configuration's credential source at the token file. Google STS exchanges it for an access token. |
| Azure | The tenant ID, subscription ID and the client ID of your user-assigned managed identity | Sets `ARM_USE_OIDC`, the IDs and `ARM_OIDC_TOKEN_FILE_PATH` (and `AZURE_FEDERATED_TOKEN_FILE`). The provider exchanges the assertion for an Azure Resource Manager token. |

No access key, service account key file or client secret is involved.

A **self-operated** runner does not need an assertion: it runs in your cloud with its own identity and
assumes the configured role directly.

### Hetzner

Hetzner authenticates with one API token. You choose how Alethia gets it when you connect:

- **Store a scoped token.** Alethia stores the token encrypted and decrypts it only when a runner
  claims the job. The runner sets `HCLOUD_TOKEN` for the job and clears it after.
- **Keep the token in your runner.** The connection stores no token. Its jobs are marked for a
  self-operated runner, and managed runners cannot claim them. Your runner reads `HCLOUD_TOKEN` from
  its own environment, so the token never enters Alethia's database.

Either way the token is long-lived and scoped to a whole Hetzner project. Hetzner is not keyless.

### Connector credentials

Credentials for a [connector](/concepts/connectors), such as a Cloudflare token, are decrypted by the
control plane at claim time and sent with the job. The runner uses them in memory for that job only.

## What it does not do

- It does not keep a credential after the job.
- It does not share a session between jobs: each job gets its own.
- It does not hold the issuer's signing key. Only the control plane does.
- It does not make Hetzner keyless.

| Property | How |
| --- | --- |
| Time-bounded | An assertion lasts 10 minutes or less; the session it buys about an hour. |
| Scoped | A credential has only the permissions of your role, service account or managed identity. |
| Revocable | Delete the role, the federation provider or the managed identity, and the next exchange fails. |
