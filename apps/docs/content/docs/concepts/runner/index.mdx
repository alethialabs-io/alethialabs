A runner is the agent that does Alethia's work: it claims jobs from the queue, gets a short-lived
credential for your cloud, runs OpenTofu, installs ArgoCD and streams logs back. It is one Go binary
in a container image, and it holds no storage key and no long-lived cloud key.

## How it works

### Where a runner runs

| | Managed | Self · deployed | Self · registered |
| --- | --- | --- | --- |
| Who runs it | Alethia, in the platform account | You, in your cloud account | You, anywhere |
| How it starts | The [warm-pool scaler](/concepts/runner/scaling) creates Hetzner VMs that register themselves | A `DEPLOY_RUNNER` job provisions it, on AWS as an ECS Fargate service | You start it, for example with `alethia runner start`, and register it for a token |
| Cloud credentials | Keyless, minted per job | Your runner's own cloud identity | Your runner's own cloud identity |
| Billing | Provisioned runner hours | Your own cloud bill | Your own infrastructure |

A self-operated runner keeps credentials inside your infrastructure. It is also the only way to run
[bring-your-own IaC](/concepts/bring-your-own-iac) without the managed sandbox, and the only runner
that can claim a Hetzner job whose token you keep to yourself. See
[Self-operated runners](/guides/runners/self-operated).

The process reads its role from `ALETHIA_RUNNER_OPERATOR` (`managed` or `self`) and the control plane
address from `ALETHIA_WEB_ORIGIN`.

### Running a job

1. **Claim.** The control plane pushes a wake signal over a server-sent events stream when a job is
   claimable; a 30-second poll covers a dropped stream. The claim is atomic, so one job runs on one
   runner. See [Job queue](/concepts/job-queue).
2. **Credentials.** The runner mints a short-lived credential for the job's cloud identity, without a
   stored key, and clears it when the job ends. See [Cloud credentials](/concepts/runner/cloud-credentials).
3. **Run.** The runner runs the job through a sandbox seam. Alethia's own templates run in the runner
   process. Your own OpenTofu or Helm runs, on the managed fleet, in a per-job container. See
   [Isolated execution](/concepts/isolated-execution). What each job type does is in
   [Job execution](/concepts/runner/job-execution).
4. **Logs.** OpenTofu output streams to the job page within about a second. See
   [Real-time updates](/concepts/realtime).
5. **Report.** The runner posts the result: status, OpenTofu outputs with secrets removed, the
   [Elench](/concepts/elench) report and timings.

### Heartbeat

A runner sends a heartbeat every 30 seconds with its version and the clouds it can serve. The
response lists jobs cancelled on the server, as a fallback when a cancel on the wake stream was
missed. The wake stream also refreshes the runner's liveness about every 10 seconds; a runner silent
for 45 seconds is marked offline. What happens to its job is in
[Job queue](/concepts/job-queue#failure-recovery).

### Shutdown

On `SIGINT` or `SIGTERM` a runner stops claiming, lets its current job finish for up to 10 minutes,
and exits. The managed fleet drains a runner before it destroys its VM, so the stop signal reaches a
runner that already finished.

### The image

Each image starts from a shared base (Alpine 3.21, non-root `runner` user) and adds one cloud's
template, already initialized so no provider downloads happen at job time. The base holds the runner
binary, OpenTofu 1.9.0 (checksum-verified), `kubectl`, Helm, Infracost 0.10.39, and a rootless
container runtime that stays unused unless the sandbox is turned on. It holds no `aws`, `gcloud` or
`az` CLI: cluster tokens are minted inside the runner process.

### Repository URLs

The runner checks every repository URL before it clones, pulls or pushes:

- The URL uses `https://`. A bring-your-own IaC repository can also use `ssh://` or
  `git@host:owner/repo`, for a deploy key. Other schemes, such as `file://`, `git://` and
  `http://`, are refused.
- The URL holds no credentials. A private repository is read through its connected git account.
- The host is a public name that resolves only to public addresses. `localhost`, `*.local`,
  `*.internal`, and private, loopback, link-local and carrier-grade NAT addresses are refused.

A self-operated runner that uses a Git server on a private network allows it with
`ALETHIA_GIT_ALLOWED_HOSTS`: a comma-separated list of host names (`git.corp.example`), wildcard
suffixes (`*.corp.example`), IP addresses or CIDR ranges (`10.20.0.0/16`). It is empty by default,
and the scheme and credential checks still apply. If an entry cannot be read, the runner refuses
every clone until it is fixed.

## What it does not do

- It does not keep cloud credentials between jobs.
- It does not hold an object-storage key. State goes through the [state proxy](/concepts/terraform-state).
- It does not verify cloud connections or keep the asset inventory. The control plane does that when
  you connect. See [Connection health and inventory](/concepts/connection-health).
