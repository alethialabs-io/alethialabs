A connector separates what a project needs, such as a DNS zone, secrets, a registry or observability,
from who provides it. You pick a provider per component; Alethia composes that provider's OpenTofu
module into the plan and skips the cloud's native resource.

## How it works

### Terms

A **connector** is a provider type in the catalog, such as Cloudflare DNS. An account you connect to
a cloud is a **cloud identity**, not a connector. See the [glossary](/reference/glossary#connectivity).

### Categories

| Category | Providers |
| --- | --- |
| DNS | Cloudflare |
| Secrets | HashiCorp Vault, Doppler, Infisical, 1Password, AWS Secrets Manager in another account, and more |
| Container registry | Docker Hub, GitHub, GitLab, Quay, Harbor, DigitalOcean, Scaleway, a generic registry, and ECR, Artifact Registry or ACR in another account |
| Helm chart registry | HTTPS and OCI registries, including Docker Hub, GitHub, GitLab and ECR |
| Observability | Datadog, Grafana Cloud |

Each provider is declared once in a catalog that the console's forms, the database and the runner all
read, so the set cannot drift between them. Observability adds to the cluster; it replaces nothing.

### Credentials

API-key credentials are stored per organization, with secret fields encrypted at rest (AES-256-GCM).
Non-secret fields, such as a Vault address, are stored in clear. A connector for another cloud
account, such as ECR in a second AWS account, uses a role or service account instead of a key.

The [configuration snapshot](/concepts/provisioning-pipeline#2-snapshot) of a job holds only the
chosen provider, never a secret. When a runner claims the job, the control plane decrypts the
credentials the project uses and sends them with the claim. The runner passes them to OpenTofu in
memory and never holds the encryption key.

### In the plan

For each component with a provider chosen, the runner copies that provider's module into the work
directory, wires it with its variables, and sets a guard variable such as `dns_provider`. The cloud
template skips its native resource when the guard names another provider. Before planning, the
provider checks that the combination makes sense and refuses one that does not.

## What it does not do

- It does not put a credential in the job's snapshot or logs.
- It does not give the runner the encryption key.
- It does not connect a cloud account. That is a [cloud identity](/guides/connectors).
