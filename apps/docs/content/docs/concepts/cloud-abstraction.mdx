You design a project once, with cloud-neutral components such as a cluster, a database and a cache.
Alethia maps each component to a service of the cloud you chose and provisions it from that cloud's
OpenTofu template.

  Cat --> AWS["AWS template: EKS, Aurora, ..."]

## How it works

The cloud catalog lists which service backs each component on each cloud. The canvas, the
[conversion between clouds](/concepts/multi-cloud-conversion) and a CI parity check all read it. A
component that a cloud cannot back is a documented exclusion: the canvas does not offer it there, and
a deploy that asks for it is refused rather than silently dropped.

The runner picks the template directory for the project's cloud and writes the design into it as
OpenTofu variables. See [Provisioning pipeline](/concepts/provisioning-pipeline) and
[Infrastructure templates](/concepts/runner/infrastructure-templates).

### Services per cloud

| Component | AWS | GCP | Azure | Hetzner |
| --- | --- | --- | --- | --- |
| Kubernetes | EKS | GKE | AKS | Talos (self-managed) |
| Network | VPC | VPC Network | VNet | Hetzner private network |
| Database | Aurora | Cloud SQL | Azure Database | CloudNativePG, in the cluster |
| Cache | ElastiCache | Memorystore | Azure Managed Redis | Valkey, in the cluster |
| NoSQL | DynamoDB | Firestore | Cosmos DB | Not offered |
| Queue | SQS | Pub/Sub | Service Bus | RabbitMQ, in the cluster |
| Topic | SNS | Pub/Sub | Service Bus | Not offered |
| Object storage | S3 | Cloud Storage | Blob Storage | Hetzner Object Storage |
| Container registry | ECR | Artifact Registry | ACR | Harbor, in the cluster |
| DNS | Route 53 | Cloud DNS | Azure DNS | Hetzner DNS |
| Secrets | Secrets Manager | Secret Manager | Key Vault | Vault, in the cluster |
| WAF | AWS WAFv2 | Cloud Armor | Azure WAF | Not offered |
| Managed certificate | ACM | Managed Certificate | App Service Certificate | Not offered |

You can replace the cloud's DNS, secrets, registry or observability with a tool you already run. See
[Connectors](/concepts/connectors).

### Hetzner is different in kind

Hetzner sells servers, private networks, DNS and object storage. It sells no managed database, cache,
queue, registry or secret store. Alethia provisions the cluster and network with OpenTofu and installs
the other services in the cluster, each as its own ArgoCD application. You design the same canvas;
what runs is different:

- **You operate the data.** A managed database is backed up, patched and failed over by the cloud. An
  in-cluster one is backed up, patched and failed over by you.
- **The secret store is only as strong as the cluster.** Hetzner has no key management service, so
  the in-cluster Vault is sealed with a key stored as a Kubernetes Secret in the same cluster. Against
  a cluster admin, an etcd backup or a volume snapshot, it protects no more than a plain Secret. It
  still gives you an audit log of reads, leases, revocation and rotation. If you need a key held
  outside the cluster, connect an external secret store.
- **Credentials are an API token, not federation.** See [Security](/concepts/security#hetzner).

### Cache and database engines

Not every cloud sells every engine, so the engine choice is narrowed per cloud rather than mapped.

| Cloud | Redis | Valkey | PostgreSQL | MySQL |
| --- | --- | --- | --- | --- |
| AWS | Yes | Yes | Yes | Yes |
| GCP | Yes | Yes | Yes | Yes |
| Azure | Yes | No | Yes | Yes |
| Hetzner | No | Yes | Yes | No |

The engine picker shows only what the selected cloud can build. A conversion to a cloud without the
engine switches it and tells you: a Valkey cache moved to Azure becomes Redis, and a MySQL database
moved to Hetzner becomes PostgreSQL.

### Cluster services after the apply

After `tofu apply`, the runner installs a set of services in the cluster through ArgoCD. Some do not
apply to every cloud. For each one, the runner records whether it was installed or skipped, and why,
and the console shows that next to the add-on status.

| Service | AWS | GCP | Azure | Hetzner |
| --- | --- | --- | --- | --- |
| external-dns | Installed (Route 53) | Installed when the Workload Identity service account exists | Installed when the managed identity exists | Installed when a Hetzner API token is connected |
| External Secrets store | Installed (Secrets Manager) | Installed (Secret Manager) | Installed (Key Vault) | Installed (in-cluster Vault) when the project declares a secret |
| Ingress | Installed (AWS Load Balancer Controller) | Skipped: install the Traefik add-on | Skipped: install the Traefik add-on, or use the Application Gateway | Skipped: install the Traefik add-on |
| Default storage class | Installed (gp3) | Built in (`standard-rwo`) | Built in (`managed-csi`) | Installed (`hcloud-volumes`) |
| ArgoCD URL | Installed (ALB ingress with an ACM certificate) | Skipped: port-forward | Skipped: port-forward | Skipped: port-forward |

## What it does not do

- It does not hide real differences. A component a cloud cannot back is refused, not faked.
- It does not offer NoSQL, topics, a WAF or a managed certificate on Hetzner.
- It does not move data between clouds. Conversion copies a design, not its data.
