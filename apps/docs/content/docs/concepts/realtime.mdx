A stream that must feel instant, such as a job's log or a support thread, is pushed to the browser:
Postgres `LISTEN/NOTIFY`, relayed over server-sent events (SSE). Everything else, such as job status,
the runner list and environment status, is polled, and polls fast only while something is in flight.

## How it works

### Log streaming

1. The runner captures OpenTofu's standard output and standard error in two buffers.
2. It sends a buffer to the control plane within about 100 milliseconds of a write, when it passes
   10 KB, and at the end of the job. A 1-second timer backs this up.
3. The control plane inserts each chunk into the job's log, and the database emits a notification on
   the `job_logs` channel with only the job and row IDs, because a notification is capped at 8 KB.
4. Each console instance holds one `LISTEN` connection per channel. On a notification, the job's SSE
   route reads the rows newer than the last one it sent and writes them to the stream.
5. The browser appends each chunk. A dropped connection reconnects on its own and resumes from the last
   row it received, so no chunk is lost or shown twice.

From OpenTofu writing a line to the browser showing it takes about 200 milliseconds. Standard error
chunks are shown in the error color.

Support threads use the same path on the `support_messages` channel. Each stream route checks that you
may see the job or case before it opens. Because each instance listens for itself, this works with
several console instances and no message broker.

The runner also writes every log line to its container's own output: `docker logs` on a managed fleet
VM, CloudWatch Logs for a self-deployed runner on ECS Fargate, or your terminal for a registered
runner.

### Poll everything else

| Data | Refresh |
| --- | --- |
| Jobs page | Every 5 seconds while a listed job is in flight, otherwise every 30 seconds |
| Shared job list (palette, overview, notifications) | Every 5 seconds while any job is in flight |
| One job | Every 3 seconds while it is `QUEUED`, `CLAIMED` or `PROCESSING` |
| Runners | Every 10 seconds while the tab is focused |
| Environment status on the canvas | Every 4 seconds while a job runs on it, otherwise every 30 seconds |

## What it does not do

- It does not push job status, runners or environment status. A change shows on the next poll.
- It does not send log contents in the notification, only IDs.
