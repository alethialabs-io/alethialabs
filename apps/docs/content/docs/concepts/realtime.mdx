# Real-time updates

The console has two ways to keep a page current. A stream that must feel instant — a job's log, a
support thread — is **pushed**: Postgres `LISTEN/NOTIFY` fanned out to the browser over SSE
(Server-Sent Events). Everything else — job status, the runner list, an environment's status — is
**polled**, and polls fast only while something is in flight.

## Push: LISTEN/NOTIFY → SSE

When a row is inserted, the database emits `pg_notify` on a named channel with a small JSON payload
that names the row, not its contents. Each console instance holds **one** dedicated `LISTEN`
connection per channel and dispatches each notification to the SSE subscribers for that key. Because
every instance listens for itself, this scales to several console instances without a message
broker. The implementation lives in `apps/console/lib/realtime/index.ts`.

Two channels are wired:

| Channel | Emitted by | Payload | SSE route |
|---|---|---|---|
| `job_logs` | the `insert_job_log` RPC | `{jobId, logId}` | `/api/stream/jobs/{id}` |
| `support_messages` | `notify_support_message()` | `{caseId, messageId}` | `/api/stream/support/cases/{id}` |

The payload carries only ids because `NOTIFY` caps a payload at 8 KB. On each notification the SSE
route reads the rows newer than the last one it sent and writes them to the stream. Each route
checks that the caller may see the job or case before it opens the stream.

For the log path end to end — the runner's buffered writer, the flush cadence, and how the viewer
renders the chunks — see [Real-time log streaming](/concepts/runner/log-streaming).

## Poll: everything else

Lists and statuses refresh through TanStack Query, which dedupes every component that asks for the
same data into one request:

| Data | Refresh |
|---|---|
| Jobs page (`useJobsPageQuery`) | every 5 seconds while a listed job is in flight; every 30 seconds otherwise |
| Shared jobs cache (`useJobsQuery`) — palette, overview, notifications | every 5 seconds while any job is in flight; idle otherwise |
| One job (`useJobQuery`) | every 3 seconds while it is `QUEUED`, `CLAIMED` or `PROCESSING`; idle once terminal |
| Runners (`useRunnersQuery`) | every 10 seconds while the tab is focused |
| Environment status (canvas) | every 4 seconds while a job is active on the environment; every 30 seconds once settled |

There is no SSE stream for job status, runners, or environments. A status change shows up on the
next poll, not instantly.
