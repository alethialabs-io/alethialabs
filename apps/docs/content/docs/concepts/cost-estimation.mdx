Alethia shows two cost figures. An environment's cost comes from Infracost, run on its last plan; a
design that has not been planned yet gets an approximate figure from list prices.

## How it works

### After a plan: Infracost

When a runner plans an environment and an Infracost API key (`INFRACOST_API_KEY`) is configured, it
runs Infracost on the plan JSON. The breakdown is stored with the plan job:

- The **cost chip** on the canvas shows the environment's monthly total from its last plan. An
  environment never planned shows **Not priced**, not `$0.00`.
- The **Plan tab** lists each priced resource with its monthly and hourly cost, most expensive first.
- The [promotion cost gate](/concepts/promotions#protection-gates) compares this total with the
  target's previous one.

Without an Infracost key, plans have no cost figure. See [Cost](/guides/design-project/cost).

### Before a plan: list prices

The assistant's design proposals and the provider comparison show an approximate monthly figure
before anything is planned. It covers the main cost drivers: the control plane, nodes, NAT gateways,
databases and caches. On AWS it uses live on-demand list prices from the public AWS pricing API,
cached for 24 hours; on other clouds, and when that API fails, it uses the prices in Alethia's cloud
catalog. A month is 730 hours.

| | List-price estimate | Infracost |
| --- | --- | --- |
| When | While you design | After a plan |
| Accuracy | Approximate, main drivers only | Every resource in the plan |
| Use | Comparing options | Reviewing before you apply |

## What it does not do

- It does not price usage. NoSQL, messaging, object storage requests and data transfer depend on use,
  and neither figure includes them.
- It does not update the cost chip when you change the design. Plan again.
- It does not price capacity created outside OpenTofu, such as nodes Karpenter launches.
