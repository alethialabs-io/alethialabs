# Limits

Alethia sets ceilings on the actions that cost the platform money, so that one account cannot use
up what every account shares. This page lists each ceiling, who it applies to, and what happens
when you reach it.

The table below is generated from the same source that the console enforces. The numbers on this
page and the numbers in the product cannot differ.

A **network** is the client network address that Alethia's edge reports for a request. A
**person** is one verified email address.

Some surfaces in this table are still being released during the beta. A ceiling applies from the
moment its surface is available to your organization.

## Per-organization limits on provisioning jobs

Besides the daily job ceiling above, Hobby organizations can run a limited number of jobs at the
same time. Extra jobs wait in the queue. They are not refused. For the numbers per plan, see
[Free plan limits](/guides/jobs/plan-and-apply#free-plan-limits).

Requests for a short-lived kubeconfig do not count toward the daily job ceiling. They have their own
rate limit, described in [Get a kubeconfig for your cluster](/guides/get-a-kubeconfig).

## Self-hosted consoles

An operator of a self-hosted console can change any ceiling with the environment variable named for
it. A positive number replaces the default. An empty value, zero, a negative number, or text keeps the
default. A value of zero does not close a surface: a mistyped value cannot stop sign-up by accident.
