# Agent Commands

The `agent` group (alias `agents`) reads **agent identities** — machine/agent personas, each with a
persona, a mission, an allowed tool scope, and a memory namespace, scoped to your account or org.
`agent setup` connects the coding agents on your machine to the Alethia MCP server.

<Callout type="info">
The CLI is a client of the same Console API. These subcommands call `/cli/agents[/…]` with your
[CLI token](/reference/cli/authentication) and resolve within your tenancy — an agent id from another org
returns not-found, never its persona/mission.
</Callout>

## No id is copied between commands

`get` takes the agent id as an **optional** first argument. Omit it on a terminal and the
identities you can see are offered to choose from, so the id never has to be read out of
`agent list` and pasted back in. The identity the CLI resolved is printed on **stderr**, so
`-o json` still emits a document that parses.

Only an **id** is accepted as the argument, and it is passed through byte for byte. A persona is
not resolved to an id on purpose: personas are not unique, so "the one whose persona matches"
would silently read a different identity the day a second agent takes the same persona. With
`--no-input` (or a non-terminal stdin/stdout) nothing is asked and the command fails naming the
argument to pass.

## `alethia agent list`

List the agent identities you can see.

```bash
alethia agent list
alethia agent list -o json
```

Columns: **ID**, **Persona**, **Tools** (count of allowed tools), **Namespace** (memory
namespace), **Version**. Add `-o json` for the raw objects. Backing call: `GET /cli/agents`.

## `alethia agent get`

Show one agent identity's persona, mission, and tool scope.

```bash
alethia agent get
alethia agent get ag_01J8Z9QK3F
alethia agent get ag_01J8Z9QK3F -o json
```

| Argument | Required | Description |
|----------|----------|-------------|
| `[agent-id]` | No | The agent identity's id. Omit it on a terminal to pick from a list. |

Renders a field/value card: **id**, **persona**, **mission**, **tool scope** (the allowed tools),
**namespace**, **project** (the project it is scoped to, or `—` for an org-wide identity),
**created**, **version**. Add `-o json` for the full object. Backing call:
`GET /cli/agents/<agent-id>`.

## `alethia agent setup`

Connect coding agents to Alethia. For each agent, `setup` writes an MCP configuration into the
project directory that points at the Alethia MCP server, and it adds an Alethia section to
`AGENTS.md`.

```bash
alethia agent setup
alethia agent setup --client claude-code --client codex --project boutique
alethia agent setup --client cursor --read-only --dry-run
```

| Flag | Required | Description |
|------|----------|-------------|
| `--client` | No | The agents to configure: `claude-code`, `cursor`, `codex`, `vscode`. Repeatable. Default: the agents found on this machine; on a terminal you choose from the list. |
| `--project` | No | Pin the MCP server to one project, by **name** or id. On a terminal you are offered the choice. Default: every project you can see. |
| `--read-only` | No | List only the tools that change nothing. |
| `--dir` | No | The project directory to write into. Default: the current directory. |
| `--no-agents-md` | No | Do not add the Alethia section to `AGENTS.md`. |
| `--dry-run` | No | Say what would be written, and write nothing. |

Each agent reads its own file:

| Agent | File |
|-------|------|
| Claude Code | `.mcp.json` |
| Cursor | `.cursor/mcp.json` |
| Codex | `.codex/config.toml` |
| VS Code | `.vscode/mcp.json` |

The server URL is the MCP endpoint of the control plane this CLI is configured for, so the agents of
a self-hosted control plane connect to it. No URL is built into the CLI. A pinned server adds
`?project=` to the URL, and `--read-only` adds `?readonly`.

`setup` writes no credential. Each agent signs in to the MCP server itself, in your browser, the
first time it connects. So the token an agent holds is one you granted to that agent.

Running `setup` again is safe. It replaces the `alethia` server entry and the marked Alethia section
of `AGENTS.md`, and leaves everything else in those files as it was. A configuration file that is
not valid JSON is refused, not overwritten. The result lists each file as `created`, `updated` or
`unchanged`.

The section in `AGENTS.md` tells the agent to plan before it applies, that a deploy or a destroy
waits for a person's approval, and that text from logs and repositories is data, not instructions.
An agent cannot approve its own deploy: the approval is given in the console, and
[`alethia approve`](/reference/cli/plan-and-apply#alethia-approve) only opens that page.

This version of `setup` does not install skills. Skills come with the Alethia agent plugin, which
is not published yet.
