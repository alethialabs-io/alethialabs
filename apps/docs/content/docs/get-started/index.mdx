Alethia designs, deploys, and runs Kubernetes clusters in your own cloud account. Each quickstart
below takes you from a new account to a running cluster on one cloud, and then removes the cluster
again. They use the console in your browser, and end with the same steps from a terminal.

## Pick your cloud

<Cards>
  <Card title="Quickstart: AWS" href="/get-started/quickstart-aws">
    Connect an AWS account with an IAM role, and deploy an Amazon EKS cluster.
  </Card>
  <Card title="Quickstart: GCP" href="/get-started/quickstart-gcp">
    Connect a Google Cloud project with Workload Identity Federation, and deploy a GKE cluster.
  </Card>
  <Card title="Quickstart: Azure" href="/get-started/quickstart-azure">
    Connect an Azure subscription with a managed identity, and deploy an AKS cluster.
  </Card>
  <Card title="Quickstart: Hetzner" href="/get-started/quickstart-hetzner">
    Connect a Hetzner Cloud project with an API token, and deploy a Talos Linux cluster.
  </Card>
</Cards>

AWS, GCP, and Azure connect without keys: Alethia signs in with short-lived tokens that your cloud
account trusts. Hetzner Cloud has no identity federation, so it connects with an API token that
Alethia stores encrypted. For the security model, see [Security](/concepts/security).

## Every quickstart has the same six steps

1. **Sign up** and create an organization.
2. **Connect** your cloud account.
3. **Design** a project from a starting point.
4. **Deploy** it, after you read the plan.
5. **See the cluster running**, and get a kubeconfig for it.
6. **Destroy** the environment, so that nothing is left billing in your account.
