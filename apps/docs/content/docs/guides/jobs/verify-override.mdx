---
title: Waive a verify control on one deploy
description: Waive named failing controls of the verify gate on one queued deploy, for a limited time, with a recorded reason.
---

Let one deploy go ahead when the [verify gate](/guides/jobs/plan-and-apply#verify-gate) fails on a
control you have decided to accept. An override waives only the control IDs you name, on one
`DEPLOY` job, for a limited time. Every other control still blocks.

<Callout type="warn">
The console and the CLI have no control that records an override yet. It is recorded by the
`recordVerifyOverride` server action, with the rules below.
</Callout>

## Before you begin

- You have the failing control IDs, for example `LEASTPRIV-001`. They are in the plan job's
  execution metadata, under `verify_result`. The [control catalog](/reference/control-catalog) says
  what each ID checks.
- The `DEPLOY` job is still `QUEUED`. No override can be set after a runner claims the job.
- Your role can edit the job.

## Steps

1. Name the failing control IDs. At least one is needed.
2. Give a reason. It cannot be empty.
3. Set how long the waiver lasts, in hours. The default is 24.

The override is refused when the list is empty, the reason is empty, the job is not found, or the
job is no longer `QUEUED`.

## What is recorded

| Field | Value |
| --- | --- |
| `controls` | The control IDs you named |
| `reason` | Your reason |
| `by` | The person who recorded it, set by the server |
| `expiry` | The time of recording plus the hours you set |

When a runner claims the job, it passes the override to the gate. The gate waives only the named
controls, and the signed [evidence receipt](/concepts/elench) of the deploy records
the waiver as an exception.

## Check that it worked

The deploy passes the gate. The waiver is listed on the **Evidence** page under
**Recorded waivers**, as **Active** until it expires.
