Find what a job type does. The console shows each type by its label. Other pages link here instead
of repeating this list. Which runner handler runs each type is in
[Job execution](/concepts/runner/job-execution).

## Before you begin

- You know where to see job types: the **Type** column and filter on the [Jobs](/guides/jobs) page,
  or `alethia jobs list`.

## Job types

| Type | Label | What it does |
| --- | --- | --- |
| `PLAN` | Plan | Runs `tofu plan` on the environment and the [verify gate](/guides/jobs/plan-and-apply#verify-gate) on the plan. Changes nothing. |
| `DEPLOY` | Deploy | Applies the reviewed plan. The verify gate runs again before `tofu apply`. |
| `DESTROY` | Destroy | Tears down the environment's infrastructure. |
| `DEPLOY_RUNNER` | Deploy Runner | Provisions a runner into your cloud account. |
| `UPDATE_RUNNER` | Update Runner | Updates a runner to a newer version. |
| `DESTROY_RUNNER` | Destroy Runner | Tears down a provisioned runner. |
| `ANALYZE_REPO` | Analyze Repo | Clones a repository and scans it for infrastructure configuration, to start a project from it. |
| `DETECT_DRIFT` | Detect Drift | Runs `tofu plan -refresh-only` and records drift. See [Drift](/concepts/drift). |
| `AUDIT` | Audit | Runs Elench on input that the job carries: a `show -json` plan or Kubernetes manifests. |
| `CHART_SCAN` | Chart Scan | Renders a bring-your-own Helm chart with `helm template`, with no secrets and no network, and checks the manifests with Elench. |
| `IAC_SCAN` | IaC Scan | Validates a bring-your-own IaC module and pins the commit it deploys from. |
| `STATE_SURGERY` | State Surgery | Repairs a broken OpenTofu state. Break-glass only. |
| `PROBE_CLUSTER` | Probe Cluster | Connects to the cluster's API server and records whether it answers. |
| `BUILD` | Build | Builds service images in the cluster with kaniko and pushes them to the project's registry. |
| `MINT_KUBECONFIG` | Mint Kubeconfig | Makes a short-lived kubeconfig credential. See [Get a kubeconfig](/guides/get-a-kubeconfig). |

## Rules worth knowing

- **Promotions** use `PLAN`, then `DEPLOY`. There is no separate type.
- **`IAC_SCAN` gates plans and deploys.** An environment with bring-your-own IaC needs a fresh scan
  that pinned the commit before a `PLAN` or `DEPLOY` can run. `DESTROY` is not gated: it uses the
  commit that made the deployed state, so a failed re-scan cannot trap live infrastructure.
- **`PROBE_CLUSTER` succeeds when the cluster is down.** It records `reachable=false`. The job fails
  only when the probe itself cannot run.
- **`BUILD`** reports one image digest per service in the job's execution metadata.
- **`STATE_SURGERY`** needs two people to approve it and is fully audited. The runner refuses it
  unless the runner sets `ALETHIA_BREAKGLASS_STATE_SURGERY_ENABLED`.
