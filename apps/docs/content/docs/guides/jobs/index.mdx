---
title: Find a job
description: Find a plan, deploy, destroy or scan job on the Jobs page, filter the list, and open the job's log.
---

Find a job and open it. Every plan, deploy, destroy, scan and runner change in Alethia is a job,
and the **Jobs** page lists them all for the organization.

## Before you begin

- Your role can view jobs. Without it, the page says so and names who can give you access.

## Steps

1. Open **Jobs** in the sidebar. To see one project's jobs, open **Jobs** from the project's menu
   instead.
2. Narrow the list with the filter bar:

   | Filter | Matches |
   | --- | --- |
   | Search | Project name or slug, environment, runner name, or the error message |
   | Date range | A preset range or a custom range. The default is the last 12 months. |
   | Authors | The member who started the job |
   | Environments, Projects | The job's target. **Projects** is hidden in a project's own list. |
   | Statuses | `QUEUED`, `CLAIMED`, `PROCESSING`, `SUCCESS`, `FAILED`, `CANCELLED` |
   | Types | Any [job type](/guides/jobs/job-types) |

   Each option shows how many jobs it matches. The filters are kept in the page URL, so you can
   share a filtered list.
3. Select a row to open the job. See [Read a job](/guides/jobs/job-detail).

The table shows each job's **Type**, **Status** with its run time, **Project**, **Runner**,
**Environment**, and **Initiated** (when, and by whom). The list updates as jobs change, without a
reload.

From the CLI, `alethia jobs list` prints the same list. See [Job commands](/reference/cli/jobs).

## Check that it worked

The job you were looking for is in the list, and selecting it opens its log.
