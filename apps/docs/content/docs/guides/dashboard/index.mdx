Find a project, a job or your usage from the organization overview, and move between a project's
pages.

## Before you begin

- You are signed in and a member of the organization. Each card and list shows only what your role
  can see, and says so when it hides something.

## Use the overview

The overview is the organization's home page. Select **Overview** in the sidebar to return to it.

| Part | What it shows |
| --- | --- |
| **Usage** card | Runner minutes this billing period, jobs running now against your plan's limit, included AI usage for the current 5-hour session and the week, projects, and seats. **Manage** or **Upgrade** opens billing. |
| **Alerts** card | The latest alert deliveries. On a plan without alerting, it says that alerting needs the Pro plan. |
| **Recent jobs** card | The latest jobs. Select one to open it. |
| **Projects** | Every project as a card or a row, with its cloud and region. |

To find a project:

1. Type in **Search projects…**, or filter by cloud or by **Repository**.
2. Sort by activity or by name.
3. Select the project to open its canvas.

The project's menu (**⋯**) opens its **Architecture**, **Jobs** or **Settings**, copies it with
**Duplicate to another cloud…**, or adds it to your favourites. Use **Create** to start a project,
connect a cloud account or invite a member.

## Use the sidebar

The sidebar has three groups:

1. **Overview**, **Clusters**, **Jobs**, **Evidence**
2. **Connectors**, **Alerts**, and **Runners** when your organization runs its own runners
3. **Usage**, **Support**, **Settings**

Inside a project, the sidebar shows the project's own pages instead:

| Page | Use it to |
| --- | --- |
| **Architecture** | Design the project on the canvas, and plan and deploy it. See [Design a project](/guides/design-project). |
| **Environments** | See each environment and its state. |
| **Jobs** | See the project's jobs. See [Find a job](/guides/jobs). |
| **Clusters** | See the project's clusters. See [Clusters](/guides/clusters). |
| **Usage** | See what the project uses. |
| **Settings** | Change the project's name, access and preview settings, and read its activity. |

## Copy a project to another cloud

1. In the project's menu, select **Duplicate to another cloud…**.
2. Pick a cloud account on another cloud, a region and a name.
3. Confirm.

Every service is translated to its native equivalent on the other cloud. Settings that do not map
directly, such as instance types, WAF rules or DNS zones, are shown as warnings. You need a
connected account on another cloud. See [Multi-cloud conversion](/concepts/multi-cloud-conversion).

## Check that it worked

The page you wanted is open, and the breadcrumb above the content names it.
