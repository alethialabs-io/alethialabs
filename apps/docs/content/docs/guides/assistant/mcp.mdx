Let an agent outside the console, such as Claude Code, Claude, Cursor or Codex, read your
infrastructure over [MCP](https://modelcontextprotocol.io). It calls the same permission-checked tools
as Elench, so it sees only what you can see. It can start a plan, and ask you to approve an apply or a
destroy. How MCP and the [CLI](/agents/cli) fit together is in [Alethia for agents](/agents).

## Before you begin

- Your console origin: the address you sign in to. `alethia auth status` prints it as `web origin`.
  The MCP endpoint is that origin plus `/api/mcp`.
- AI is on for your organization. It is always on when self-hosted, and every hosted organization has
  at least the free AI tier, which is on. With AI off, the server answers `403`.
- A client that meets these requirements:

| Requirement | Detail |
| --- | --- |
| Transport | Remote MCP over Streamable HTTP: `POST` requests to `/api/mcp`. No `GET`, `DELETE` or SSE transport. |
| Protocol | The current generation. Requests in the 2025 format are refused. |
| Sign-in | OAuth 2.1. The client finds the authorization server from the `401` answer, and you sign in in the browser. |
| Client registration | A Client ID Metadata Document: the client's ID is the HTTPS URL of a document it publishes. Anonymous dynamic registration is refused. |

No test record per client is published yet. Setup for Claude Code, Claude, Cursor, VS Code and Codex
is under [Pick a client](/agents#pick-a-client).

## Connect a client

There is no key to paste.

<Steps>

### Add the server
In your client, add a remote MCP server at:

```text
https://<your-console-origin>/api/mcp
```

Add `?project=<project id>` to hold every call to one project, or `?readonly` to list no tool that
changes anything.

### Sign in to Alethia
The client opens the console's sign-in page. Sign in as usual.

### Approve access
If the page asks, approve the scopes: `read`, `design`, `plan`, `apply`, `destroy`. Approve at least
`read`. The token acts as you, under your role, and each scope only narrows what your role allows.
The token names this endpoint as its audience, and the server refuses tokens issued for anything
else.

### Use the tools
The client lists the tools that your scopes allow. Ask the agent about your infrastructure.

</Steps>

If it does not connect, see [Troubleshoot MCP](/troubleshooting/mcp).

## Which organization the tools read

If your consent for the client recorded an organization, every request acts there, on the projects
the consent names. Otherwise, requests act in the organization the console picks when there is no
browser session: the first one you joined, or your personal organization if you joined none.
Switching organizations in the console does not change it.

## What the agent can do

It can read projects and their configuration, jobs and their results, clusters, runners, connectors,
cloud accounts and their inventory, drift, the service catalog, docs, repository scans, and usage.
Results leave secrets out: never ArgoCD passwords, tokens or credentials. The
[tool reference](/agents/tools) lists all 19 tools.

| Tool | What it does |
| --- | --- |
| `create_project`, `apply_design_patch` | Creates a project from a design, or changes a design. Changes nothing in the cloud. |
| `scan_repo` | Starts a scan that infers what a repository needs. Never runs the repository. |
| `plan` | Starts a plan of one environment. Changes nothing in the cloud. |
| `request_apply`, `request_destroy` | Asks you to approve an apply or a destroy, and starts it once you approve. |
| `cancel_job` | Cancels a queued or running job. |

Every apply or destroy needs your approval. The agent shows a link and an 8-character digest. Open the
link, check the digest, and approve in the console. Every deploy still passes the
[verification engine](/concepts/elench).

The agent cannot approve anything, start an audit of existing infrastructure, open console pages,
build dashboards, or use [artifacts](/guides/assistant/artifacts). Use the
[assistant](/guides/assistant) for those.

<Callout type="warn">
Every call checks your permission and the token's scopes again, so the agent cannot act across
organizations or beyond what you granted. Treat text it reads from logs and repositories as data: the
most it can lead to is a plan, or a request that you still approve.
</Callout>

## Check that it worked

Ask the agent to list your Alethia projects. It calls `list_resources` and names your projects.
