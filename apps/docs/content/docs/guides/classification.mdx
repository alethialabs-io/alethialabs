---
title: Classify resources
description: Define dimensions and their allowed values once, then label projects, clusters, cloud identities, runners, members and more from that closed list.
---

Label your resources from one list that an admin controls, instead of free-form tags. An admin
defines **dimensions**, such as *Environment*, and the **values** each one allows, such as `dev`,
`staging` and `prod`. People then **assign** those values to resources. So `env=prod`,
`Environment=Production` and `PROD` cannot all appear.

## Before you begin

- To define dimensions and values, you need the Editor role (`org:edit`). Everyone else sees a
  read-only view.
- To assign a value, you need `org:edit` and the right to edit that resource. Without both, you see
  the values but no picker.

## Define the dimensions

<Steps>

### Open the page
Open **Settings → Classification**. On an empty page, you can start from a template: Environment,
Data classification, Team or Cost center.

### Create a dimension
Give it a label. The `key` fills in from the label, and cannot change after you create the
dimension, so choose it with care. Add a description if you like, and choose the mode:

| Mode | A resource holds | Example |
| --- | --- | --- |
| Single | At most one value. A new value replaces the old one. | *Environment*: one of dev, staging or prod |
| Multi | Any number of values | *Team*: platform and payments |

### Add values
Type a label and press Enter. To set the slug or a color, open the value's editor.

### Put them in order
Drag dimensions and values. Every picker shows them in this order.

</Steps>

<Callout type="warn">
Deleting a dimension deletes its values and every assignment of them. Deleting a value removes it
from every resource. Neither can be undone.
</Callout>

## Assign values

Open the resource and use its classification picker:

| Resource | Where |
| --- | --- |
| Projects | Project → **Settings → General** |
| Environments | A project's **Environments** |
| Clusters | **Clusters** |
| Cloud identities and connector credentials | **Connectors** → the account in the detail sheet |
| Runners | **Runners** |
| Members, Roles | **Settings → Members**, **Settings → Roles** |
| Alert policies, alert channels | **Alerts → Policies**, **Alerts → Channels** |
| Support cases | The case's detail |

Alert deliveries and runner usage sessions cannot be classified: they are records, not things you
manage. From the CLI, see [Classification commands](/reference/cli/classification).

## What classification does not do

<Callout type="warn">
Classification does not enforce anything. No permission check, policy, provisioning step or
verify gate reads the labels. They describe your resources; they do not control them.
</Callout>

## Check that it worked

The resource shows the value as a chip. On **Settings → Classification**, each value shows how many
resources carry it. Select the count to see which kinds of resource. Each dimension shows its
coverage, and unused values are marked, so you can delete or reuse them.
