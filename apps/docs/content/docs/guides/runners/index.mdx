title: Add and manage runners
description: Deploy a runner into your AWS account or register one you run anywhere, then watch its status, update it, and remove it.
---

Add a runner, the agent that runs your jobs, and keep it healthy. Every plan, deploy and scan runs
on a runner. How a runner works is in [Runner](/concepts/runner).

## Before you begin

- Your organization runs its own runners. The **Runners** item appears in the sidebar only then; the
  page is still at `/{org}/~/runners`.
- To deploy a runner, you have a verified AWS [connection](/guides/connectors/aws) and a runner
  that is already online to run the deploy.

## Choose the kind of runner

| Kind | Where it runs | How it is added | Updates | Billing |
| --- | --- | --- | --- | --- |
| **Managed** | Alethia's Hetzner servers | A [warm pool](/guides/fleet-pools) creates and removes it | The pool replaces it with a new version | By the hours it is provisioned |
| **Self · Deployed** | One ECS Fargate task in your AWS account | **Add runner → Deploy to a cloud** | **Update all** rolls it in place | Your AWS bill |
| **Self · Registered** | Any host you run, on any cloud or on premises | **Add runner → Register your own** | You replace the binary or image | Not billed by Alethia |

A deployed runner is AWS only, because the runner template exists only for AWS. This limits where
the runner runs, not what it provisions: a registered runner in any place provisions every cloud
Alethia supports. A deployed runner is one task that does not scale with the queue. Only managed
runners scale. See [Scaling](/concepts/runner/scaling).

## Add a runner

<Tabs items={["Deploy to a cloud", "Register your own"]}>
  <Tab value="Deploy to a cloud">
    <Steps>

    ### Open the dialog
    On **Runners**, select **Add runner**, then **Deploy to a cloud**.

    ### Pick the account
    Choose the AWS **Cloud account** and the region. Only verified AWS accounts are listed.

    ### Deploy
    Select **Deploy runner**. An online runner runs a `DEPLOY_RUNNER` job, which creates the ECS task
    definition, IAM roles, a CloudWatch log group and security groups. After about two minutes, the
    new runner shows **Online**.

    </Steps>

    From the CLI, use `alethia runner deploy`. It refuses any cloud other than AWS, as the console does.
  </Tab>
  <Tab value="Register your own">
    <Steps>

    ### Open the dialog
    On **Runners**, select **Add runner**, then **Register your own**.

    ### Name it
    Enter the **Runner name** and select **Register runner**.

    ### Save the credentials
    Copy the **Runner ID** and **Runner Token**. The token is shown once and cannot be recovered. If
    you lose it, register the runner again.

    ### Start the runner
    Set the credentials as environment variables on your host and start the runner. See
    [Self-operated runners](/guides/runners/self-operated).

    </Steps>
  </Tab>
</Tabs>

## Watch your runners

Filter the runner cards by name, **Cloud**, status (**Online**, **Offline**, **Draining**), operator
(**Managed**, **Self · Deployed**, **Self · Registered**), **Region** and **Version**. The page
updates by itself.

| Status | Meaning |
| --- | --- |
| **Online** | Ready for jobs. The runner holds a connection to the console that refreshes about every 10 seconds. |
| **Draining** | Finishes its current job and takes no new ones. |
| **Offline** | The connection dropped, or nothing was heard for 45 seconds. Its jobs go back in the queue. |

While a job acts on a runner, its card shows **Provisioning…**, **Updating…** or **Destroying…**.
Each card also shows the runner's operator, its clouds (or **Any**), the region for a managed runner,
its version, its active job, and its provisioned hours or when it was last seen.

## Update runners

Each runner reports its version. Select a version on a card to read its release notes; an outdated
runner shows that an update is available. The **Versions** panel shows the **Latest release** and a
**Changelog**. When runners are behind, **Update all** queues an `UPDATE_RUNNER` job for each
deployed runner that can be updated in place. Runners it cannot update are marked as needing a new
deploy. Managed runners are replaced by their pool.

## Set a default or remove a runner

- **Set as default** marks the runner that a job uses when you pick none. **Clear default** undoes it.
- **Destroy** tears down a deployed runner's cloud resources through a `DESTROY_RUNNER` job. You
  choose which runner runs the destroy.
- **Remove** deletes a registered runner, so it is no longer given jobs.

## Check that it worked

The new runner's card shows **Online**. Queue a plan: its job page shows the runner that claimed it.
