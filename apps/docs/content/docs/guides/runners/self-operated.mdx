title: Run your own runner
description: Run a registered runner on a host you operate, on any cloud, on premises or air-gapped, with the environment variables it reads.
---

Run the runner binary or image on a host you control. A registered runner provisions every cloud
Alethia supports, wherever it runs. It connects out to the console over HTTPS, so it needs no
inbound port.

## Before you begin

- You registered the runner and have its **Runner ID** and **Runner Token**. See
  [Add and manage runners](/guides/runners#add-a-runner).
- The host can reach the console over HTTPS.
- If you run the binary instead of the official image, the host has these tools. The runner needs no
  cloud CLI (`aws`, `gcloud` or `az`): it gets cloud credentials itself, keylessly.

| Tool | Purpose | Version |
| --- | --- | --- |
| OpenTofu (`tofu`) | Provisioning | 1.9 or later |
| `kubectl` | Cluster access | Matches your clusters |
| Helm | Installs ArgoCD and cluster components | Any current |

The official image bundles all three and a cache of OpenTofu providers.

## Steps

<Steps>

### Set the environment

```bash
export ALETHIA_WEB_ORIGIN=https://alethia.example.com
export ALETHIA_RUNNER_ID=<runner-id>
export ALETHIA_RUNNER_TOKEN=<runner-token>
export ALETHIA_RUNNER_OPERATOR=self
```

### Start the runner

```bash
./runner
```

The runner confirms its registration, keeps a connection to the console, and sends a heartbeat
every 30 seconds. A wake on that connection starts a job within a second. A poll every 30 seconds is
the fallback.

</Steps>

The runner holds no object-storage credentials. OpenTofu state goes through the console's state
proxy, with a token for each job. See [Cloud credentials](/concepts/runner/cloud-credentials).

## Environment variables

| Variable | Required | Description |
| --- | --- | --- |
| `ALETHIA_WEB_ORIGIN` | Yes | The console's base URL |
| `ALETHIA_RUNNER_ID` | Yes | The runner ID from registration |
| `ALETHIA_RUNNER_TOKEN` | Yes | The runner token from registration |
| `ALETHIA_RUNNER_OPERATOR` | No | `self`, the default. The older `ALETHIA_RUNNER_MODE=self-hosted` still works. |
| `ALETHIA_RUNNER_PROVIDERS` | No | The clouds this runner serves, separated by commas, such as `aws`. Unset means any. |
| `ALETHIA_RUNNER_SLOTS` | No | Jobs at once (default `1`). Above `1`, each job runs in its own worker process: run the container with an init (`docker --init`, or `init: true` in Compose) so that stray tools are cleaned up. |
| `ALETHIA_RUNNER_INSTANCE_ID` | No | A separate ID for each runner when several share a host |
| `ALETHIA_HELM_REGISTRY_ALLOW_PRIVATE` | No | `1` lets chart pulls reach a registry on a private network, such as Harbor on RFC 1918 addresses. Off by default. Loopback and link-local addresses, including cloud metadata, stay blocked. See [Chart repositories](/guides/connectors/chart-repositories). |
| `INFRACOST_API_KEY` | No | Turns on cost estimates for plans |
| `HCLOUD_TOKEN` | No | A Hetzner API token that this runner uses, so that Alethia does not store one |

## Common setups

| Setup | What to do |
| --- | --- |
| **On premises** | Run the runner on a bastion host or a CI machine inside your network. OpenTofu then reaches resources on the internal network. |
| **Air-gapped** | Download OpenTofu providers and modules in advance, set up a local provider mirror, and give the runner an approved network path to the console. |
| **Hetzner token kept by you** | Set `HCLOUD_TOKEN` on this runner. Jobs for a Hetzner connection that has no stored token are marked as needing a self-operated runner, so managed runners never take them. |
| **Local development** | Run the runner next to a development console, with `ALETHIA_WEB_ORIGIN=http://localhost:3000`. |

## Check that it worked

The runner's card on **Runners** shows **Online** within a few seconds of the start. Its log on
stdout shows that it registered.
