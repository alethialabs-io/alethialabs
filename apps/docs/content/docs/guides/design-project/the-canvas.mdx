Design one environment on the **Architecture** canvas, then plan and deploy it. What the cards,
rules and status dots mean is in [Read the canvas](/concepts/canvas).

## Before you begin

- You have a project. The cloud account is chosen when you create the project, and you cannot
  change it on the canvas.
- To deploy, a runner is online for your organization. See [Runners](/guides/runners).

## Find your way around

One environment is one Kubernetes cluster inside one network. The board stands for both, so
neither is a card.

```text
     [ environment | Select Hand | Add Connect | Undo Redo | Tidy Fit | Run Sources | ⌘K ? ⋯ ]

   ┌────────────────────────────────────────────────────────┐ ┌──────────────────┐
   │                       the cards                        │ │  the inspector   │
   │                                                        │ │  (or the review  │
   │         [ Pending changes · 3   Discard  Review plan ] │ │   view)          │
   └────────────────────────────────────────────────────────┘ └──────────────────┘
```

| Area | What it does |
| --- | --- |
| **Toolbar**, top centre | Starts with the environment's name: select it to size the cluster and the network. Then the select and hand tools, **Add**, **Connect**, **Undo**, **Redo**, **Tidy layout**, **Fit view**, the **Run** menu (plan, audit, detect drift, probe the cluster), **Sources**, the command palette, the shortcut list and the **⋯** menu. A disabled tool's tooltip says why. On a narrow window some tools move into the **⋯** menu and the command palette. |
| **Inspector**, right | Opens when you select a card. See [Use the inspector](/guides/design-project/node-inspector). |
| **Changes bar**, bottom centre | Shows **Pending changes** with a count, **Not deployed yet**, **Saved, not deployed**, **Up to date**, **Deploying** or **Deploy failed**. Offers **Review plan**, and with changes pending also **Discard** and **Save**. A button counts any design problems. |
| **Review view**, right | Replaces the inspector when you select **Review plan**. |

## Start an empty board

An empty board offers three ways to start:

- **Start from a template** sizes the cluster from a starter template. It changes the cluster, not
  the cards.
- **Add the first piece yourself** opens the **Add** picker.
- **Bring your own** attaches a [Helm chart](/guides/design-project/bring-your-own-charts) or a
  [bring-your-own IaC module](/guides/design-project/bring-your-own-iac).

A link to the board can carry a starting point (`?seed=…`). The board applies it once and removes
it from the address.

## Add a resource

1. Select **Add** in the toolbar, or press **A**. You can also press **⌘K** and type a service name,
   such as `postgres`, `redis` or `s3`.
2. Pick the resource. For a database or a cache, pick the engine.

The card appears on the board and the inspector opens on it. The picker lists only what your
project's cloud can run. A resource already on the board that can exist once is disabled, and a
resource that is not available yet shows **Soon**.

On Hetzner, databases, caches, queues, topics, NoSQL tables, the registry and secrets run inside
your cluster, and their cards say so (for example `Runs as · CloudNativePG`).

## Connect a service to what it uses

A service connects to a database, a cache, a queue or a secret. At deploy, Alethia gives the
service that resource's endpoint and credentials without a stored key.

1. Drag from the handle at the bottom of the service card.
2. Release on the card you want to connect to. While you drag, the card under the pointer says
   whether you can connect to it.
3. In the inspector's **Connections** tab, choose what the service gets from the resource.

If you release on empty board, a menu offers what the service can connect to, including a new
resource placed where you let go. Without a pointer, select the service and press **C**.

To remove a connection, select the line and press **Delete**, or select **Remove connection**.

## Review and deploy

1. Select **Review plan** on the changes bar, or press **⌘S**.
2. Check the design changes at the top of the review view.
3. Select **Run plan**. This saves the design and shows what would change in the cloud.
4. Select **Deploy**. It applies exactly that plan, and is enabled only for a current plan you
   reviewed. When it is disabled, the view says why.

If you open a card while the review is open, the review steps aside until you close the card.

## Keyboard

Press **Tab** to move between cards and lines. Letter keys do nothing while you type in a field.
On Windows and Linux, read **Ctrl** for **⌘**.

| Key | Does |
| --- | --- |
| **Enter** | Opens the focused card. On a line, opens the service it starts from. |
| Arrow keys | Move the selected cards. **Shift** makes a larger step. |
| **Delete** or **Backspace** | Removes the selection. |
| **C** | Connects the selected service. |
| **A** | Opens the **Add** picker. |
| **V** / **H** | Select tool / hand tool. Hold **Space** to pan. |
| **⇧L** / **⇧1** | Tidy layout / fit view. |
| **⌘Z** / **⇧⌘Z** | Undo / redo. |
| **⌘D** | Duplicates the selection. |
| **⌘S** | Opens the review view. |
| **⌘K** | Opens the command palette. |
| **⌘I** | Asks the AI assistant. |
| **Esc** | Closes the inspector. |
| **?** | Lists every key. |

## Check that it worked

After the deploy, the changes bar reads **Up to date** and each card shows a solid dot. A card
with a hollow-centre dot failed: open it and read **Status**.
