---
title: Bring your own IaC
description: Provision an environment from your own OpenTofu root module instead of the built-in template, behind a static safety scan.
---

Point an environment at your own OpenTofu root module in Git. Alethia then scans, plans and applies
your module instead of its built-in template. The module replaces the template for that
environment. Why the safety gate exists, the variable and cluster-output contracts, and who may run
a module are in [bring-your-own IaC](/concepts/bring-your-own-iac).

## Before you begin

- Your operator set `ALETHIA_BYO_IAC_ENABLED=true` for your instance. Without it, attaching,
  scanning and provisioning a module are refused.
- The module's [Git provider is connected](/guides/connectors/git-providers). If none is, the
  repository step offers to connect one.
- The environment has no deployed or in-progress template infrastructure. Destroy it first.

## Write a minimal module

This module needs no cloud and costs nothing, so you can test attach, scan, plan, deploy and destroy.
Put it in a directory such as `envs/dev/`:

```hcl
terraform {
  required_providers {
    random = { source = "hashicorp/random" } # on the default allowlist
  }
  # No backend block: Alethia sets its own state backend.
}

# Platform context from Alethia. Declare only what you use.
variable "alethia_project"     { type = string }
variable "alethia_environment" { type = string }

# Your own variables must not start with alethia_.
variable "greeting" {
  type    = string
  default = "hello"
}

resource "random_pet" "name" {
  prefix = "${var.alethia_project}-${var.alethia_environment}"
}

output "pet"      { value = random_pet.name.id }
output "greeting" { value = var.greeting }
```

To provision a cluster, emit the outputs in
[the cluster-output contract](/concepts/bring-your-own-iac#the-cluster-output-contract), and give the
runner's identity cluster-admin as
[your module must self-admin the cluster](/concepts/bring-your-own-iac#required-your-module-must-self-admin-the-cluster)
describes.

## Attach the module

1. On the canvas, press **⌘K** and choose **Bring your own IaC** in the **Sources** group.
2. On **Repository**, choose the repository.
3. On **Path & ref**, set the root-module path (empty for the repository root) and, optionally, a
   branch, tag or commit (empty for `HEAD`).
4. On **Variables**, add any tfvars the module needs, or none to use its defaults:

   | Field | Rule |
   | --- | --- |
   | **Name** | Letters, digits and underscores, starting with a letter or underscore. Unique. |
   | **Type** | `string`, `number` or `bool` |
   | **Value** | Must parse as the type |

   These are stored as plain tfvars, so never put a secret here.
5. On **Review**, check the summary and select **Attach source**.

A safety scan starts on its own.

## Read the safety scan

The module appears as an **External IaC** card with its repository, ref, path, the commit the scan
pinned, and a scan status. Select the status to open **IaC safety scan**. It runs the
[static safety gate](/concepts/bring-your-own-iac#the-static-safety-gate) and `tofu validate` on the
pinned commit, and shows:

- A verdict: **No blocking issues found**, or **Issues found — resolve before deploying**.
- The `tofu validate` result and a count per severity. An `error` blocks the deploy; a `warning`
  does not.
- Each finding, worst first, with a rule ID, `file:line` and a message.
- The providers and modules it found.

After you push a fix, select **Rescan**. Only a clean scan pins a commit for deploys. A failed scan
clears the pin, so nothing deploys until a clean scan, and what deploys is exactly the commit
scanned.

## Plan and deploy

While the module is attached, the environment's plan, deploy and destroy run your module. Its
resources appear as read-only cards, and the **Add** picker is disabled, because the module is the
source of truth. Each deploy's **Plan** tab carries the same verify verdict as a template deploy.
The **External IaC** card shows **DEPLOYED** or **NOT DEPLOYED**, and the commit the last deploy
applied.

## Detach the module

To go back to the built-in template, open the **External IaC** card and select **✕**. You can
detach only a module that has never deployed. Otherwise, destroy the environment first.

## Check that it worked

After a deploy, the **External IaC** card reads **DEPLOYED**, and the applied commit matches the
pinned one. For the minimal module, the plan output shows `pet` and `greeting`.
