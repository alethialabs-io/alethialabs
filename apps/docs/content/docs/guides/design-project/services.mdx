title: Add a service
description: Run your own code on the cluster, built from a repository or deployed from an image, with ports, environment variables, bindings, resources and a health check.
---

Add a service to run your own code on the environment's cluster. Alethia builds it from a
repository, or deploys an image you already pushed, and turns it into Kubernetes manifests at
deploy.

## Before you begin

- To build from a repository, connect its [Git provider](/guides/connectors/git-providers).

## Steps

1. On the [canvas](/guides/design-project/the-canvas), select **Add**, then **Service** in the
   **Workloads** group. The inspector opens on the new card.
2. Under **Identity**, enter a **Name**, unique in the environment, and choose a **Type**:

   | Type | Use it for |
   | --- | --- |
   | **Deployment** (default) | Long-running, load-balanced workloads |
   | **Job** | A task that runs once to completion |
   | **CronJob** | A task that runs on a schedule |
   | **StatefulSet** | A workload that needs a stable identity and storage |

3. Under **Source**, choose where the image comes from:
   - **Repository**: enter the **Repository URL** and, optionally, the **Path** to build from.
     Under **Build**, you can set the **Dockerfile** path and the build **Context**. Alethia builds
     and pushes the image without a stored key.
   - **Prebuilt image**: enter the **Image**, such as `ghcr.io/org/api:1.4.0`. It deploys as-is.
4. Under **Networking**, add each **Container port** (1–65535), with an optional **Protocol**
   (`TCP` or `UDP`) and **Name**.
5. Under **Environment**, add plain **Variables** as name and value pairs. Do not put credentials
   here: use a binding.
6. Under **Bindings**, connect the service to a database, cache, queue or secret, and map an
   environment variable to each value you need. You can also draw the connection on the board.

   | Value | Delivered as |
   | --- | --- |
   | `endpoint`, `port` | A value in the manifest |
   | `username`, `password`, `connection string` | A Kubernetes `secretKeyRef`, never written into the manifest |
   | `value` (a secret's value) | A Kubernetes `secretKeyRef` |

   A binding can also target a resource from a
   [bring-your-own IaC module](/guides/design-project/bring-your-own-iac). Each value then maps to
   one of the module's outputs.
7. Under **Runtime**, set **Replicas** (1–5, default 2). Optionally set **CPU request**,
   **Memory request**, **CPU limit** and **Memory limit** as Kubernetes quantities, such as `100m`
   or `128Mi`. Unset values use the template's defaults.
8. Optional: under **Health**, turn on **Health check** to gate the rollout on a probe. Choose
   **HTTP** with a **Path** such as `/healthz`, or **TCP**, and set the **Port**.

## Check that it worked

After a deploy, the service card shows a solid dot. Check the workload:

```bash
kubectl get deployments --all-namespaces | grep <service-name>
```

The ready count matches **Replicas**.
