title: Use a starter template
description: Copy one of three public template repositories to start an apps repository, a bring-your-own Helm chart, or an AI retrieval stack.
---

Start from one of Alethia's three public template repositories instead of an empty repository.
Each one holds only paths that Alethia reads.

## Before you begin

- You have a GitHub account, and its [Git provider is connected](/guides/connectors/git-providers).

## Choose a template

| Repository | What it is | Attach it as |
| --- | --- | --- |
| [alethia-starter-apps](https://github.com/alethialabs-io/alethia-starter-apps) | An apps repository that ArgoCD syncs | [Apps repository](/guides/design-project/repositories) |
| [alethia-starter-chart](https://github.com/alethialabs-io/alethia-starter-chart) | A Helm chart with a Deployment, a Service and a ConfigMap | [Bring-your-own chart](/guides/design-project/bring-your-own-charts) |
| [alethia-starter-ai](https://github.com/alethialabs-io/alethia-starter-ai) | A retrieval-augmented generation stack | Both |

All three are Apache-2.0. Each has a `TEMPLATE_VERSION` file and a `CHANGELOG.md`. A change to a
chart's `values.schema.json` is a major version, because your values are written against it.

When you create a project with **Start from a template**, the **Template** choice points you to a
starter. **Standard** points to alethia-starter-apps, **AI Workloads** to alethia-starter-ai, and
**Custom** to none. The choice does not change the cluster: all three make the same node pool, with
no GPU.

Where code goes decides what it may create. An apps repository may create cluster-scoped resources,
such as CustomResourceDefinitions. A bring-your-own chart may create only namespaced workload kinds,
so a chart that installs an operator cannot be one. See
[What your manifests may create](/concepts/apps-repository#what-your-manifests-may-create).

## Use the apps template

1. On the repository page, select **Use this template** to make your own copy.
2. Add a **Repository** card and set **ArgoCD apps repository** to your copy. Leave
   **Overlay path** empty.
3. Deploy.

| Path | Purpose |
| --- | --- |
| `kustomization.yaml` | The root manifest. Without it, the root Application manages nothing. |
| `namespace.yaml` | The namespace the root delivers into |
| `base/` | The application, defined once |
| `overlays/dev/`, `overlays/staging/` | Discovered as `apps-dev` and `apps-staging` |
| `addons/` | Keeps the `addons` Application out of ComparisonError |

## Use the chart template

1. Select **Use this template** to make your own copy.
2. Run `hack/check-byo-contract.sh` against your chart before you attach it. It fails if a change
   breaks the bring-your-own contract. Its list of kinds differs slightly from Alethia's: it accepts
   `Endpoints` and `NetworkPolicy`, which Alethia refuses, and refuses `DaemonSet`, which Alethia
   accepts.
3. On the canvas, press **⌘K** and choose **Bring your own Helm chart**.
4. Choose your repository, set **Chart path** to `chart`, and set **Ref** to `HEAD` or a tag.
5. Deploy.

## Use the AI template

The stack holds a vector database, a CPU embedding server, CPU inference, model serving and job
queueing. It splits across both places:

| Component | Goes in | Why |
| --- | --- | --- |
| KServe, Kueue, the GPU operator | `addons/` in the apps repository | They install CustomResourceDefinitions |
| Qdrant, embeddings, inference, the RAG application | `chart/`, as a bring-your-own chart | Only Deployments, Services and PersistentVolumeClaims |

1. Copy the repository, then attach it as an apps repository and its `chart/` directory as a
   bring-your-own chart.
2. Make sure cert-manager is installed, because KServe needs it for its admission webhook:

   | You created the project | Do this |
   | --- | --- |
   | From **AI Workloads** | Nothing. Alethia installs cert-manager on every cloud, with no domain needed. |
   | Any other way | On the DNS card, set **Domain name** and turn on **Managed TLS certificate**. This works on AWS, GCP and Azure. |

   Do not add cert-manager to `addons/`: a second copy fights the platform's copy.
3. Deploy.

The template is CPU-only. A GPU node pool is the costliest thing to provision by accident, so you
add one yourself: see the repository's `gpu/` directory.

On Hetzner, the cluster the template was last tested on (three `cpx32` servers in `nbg1`) cost
EUR 0.1707 an hour for servers only. That excludes public IPv4 addresses and volumes, and it is the
whole cluster, which ran all three templates. The figure and its source are in the
[proof bundle](https://github.com/alethialabs-io/alethialabs/tree/main/demos/proofs/templates/ai/20261001T200301Z).

## Check that it worked

In ArgoCD, the root Application and each discovered overlay (`apps-dev`, `apps-staging`) are
**Synced** and **Healthy**. A chart shows a passed safety scan on its card.
