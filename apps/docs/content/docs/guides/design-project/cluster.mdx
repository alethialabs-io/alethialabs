---
title: Configure the cluster
description: Set the Kubernetes version, node size, node count, capacity type, disk and cluster admins for an environment's cluster.
---

Size the Kubernetes cluster that the environment runs on. To add more node pools, labels or
taints, see [Add node pools](/guides/design-project/node-pools).

## Before you begin

- You have a project open on the [canvas](/guides/design-project/the-canvas).

## Steps

1. Select the environment's name at the start of the toolbar. The cluster settings are on
   **Settings**.
2. Choose the **Kubernetes version**. The default is 1.35. On Hetzner the field is read-only: Talos
   installs Kubernetes 1.35.6.
3. Size the nodes in one of two ways:
   - Choose an **Instance type**. Each option shows its vCPU and memory.
   - Or set **vCPU per node** (1–96) and **Memory per node** (1–768 GB). The runner picks the
     nearest instance type on the project's cloud. This setting works on every cloud, so it
     survives a move to another cloud.
4. Set **Min nodes**, **Desired nodes** and **Max nodes**. Each is 1–100, and min ≤ desired ≤ max.
   The defaults are 2, 2 and 5.
5. Choose **Capacity**: **On-demand** (the default) or **Spot**. Spot nodes cost less, but the cloud
   can take one back at short notice. On Azure, Spot adds a separate Spot pool and the system pool
   stays on-demand. Spot is not available on Hetzner or on a GKE Autopilot cluster.
6. Optional: set **Node disk**, the worker root volume in GB. Leave it empty for the cloud's default.
   Hetzner has no such field, because the disk comes with the server type.
7. Optional: under **Security**, add **Cluster admins**. They get cluster-admin access when the
   cluster is created.

### Versions and instance types

The version and instance type lists come from your cloud account when Alethia can read them. When
it cannot, the lists are these:

| Cloud | Versions | Default type | Types |
| --- | --- | --- | --- |
| AWS | 1.33–1.35 | `t3.large` | `t3.medium`, `t3.large`, `t3.xlarge`, `m5a.large`, `m5a.xlarge`, `c5.large`, `c5.xlarge`, `r5.large`, `g4dn.xlarge` |
| GCP | 1.33–1.35 | `e2-standard-2` | `e2-medium`, `n1-standard-1`, `e2-standard-2`, `e2-standard-4`, `n2-standard-2`, `n2-standard-4`, `c2-standard-4`, `n2-highmem-2`, `a2-highgpu-1g` |
| Azure | 1.33–1.35 | `Standard_D2s_v5` | `Standard_D2s_v5`, `Standard_D4s_v5`, `Standard_D8s_v5`, `Standard_D2as_v5`, `Standard_D4as_v5`, `Standard_F2s_v2`, `Standard_E2s_v5`, `Standard_E2s_v3`, `Standard_NC4as_T4_v3` |
| Hetzner | 1.35 | `cpx22` | `cax11`, `cax21`, `cax31`, `cx23`, `cx33`, `cpx22`, `cpx32` |

On GCP, a deploy onto `e2-medium` or `n1-standard-1` is refused before it spends anything. GKE
reserves most of their CPU, so the cluster add-ons cannot run. `e2-standard-2` is the smallest
shape that works.

The disk floor and default per cloud:

| Cloud | Minimum | Default |
| --- | --- | --- |
| AWS, GCP | 20 GB | 50 GB |
| Azure | 30 GB | 100 GB |

The maximum is 2,000 GB.

### Cluster admins

| Cloud | Enter | Granted |
| --- | --- | --- |
| AWS | IAM user or role ARNs, or IAM user names | The `system:masters` group |
| GCP | Google account email addresses | `roles/container.admin` |
| Azure | Microsoft Entra object IDs | Cluster admin RBAC |

### What each cloud builds

| Cloud | Service | Autoscaling | Identity |
| --- | --- | --- | --- |
| AWS | EKS with managed node groups | Karpenter | IAM roles for service accounts, with an OIDC provider |
| GCP | GKE | GKE Autopilot | Workload Identity |
| Azure | AKS | Cluster Autoscaler | Microsoft Entra integration for RBAC |
| Hetzner | Talos Linux on Hetzner Cloud servers | None: a fixed number of servers | — |

## Check that it worked

Run a plan from the review view. It shows the cluster and node group to create, and its cost. After
the deploy, [get a kubeconfig](/guides/get-a-kubeconfig) and run `kubectl get nodes`: you see the
desired number of nodes.
