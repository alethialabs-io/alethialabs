---
title: Add queues and topics
description: Add message queues, with ordered delivery if you need it, and publish/subscribe topics with their subscriptions.
---

Add queues for point-to-point messages and topics for publish/subscribe. You can add as many of
each as you need.

## Before you begin

- You have a project open on the [canvas](/guides/design-project/the-canvas).
- If you want ordered delivery, your publisher can set an ordering key on every message.

## Add a queue

1. Select **Add**, then **Queue** in the **Messaging** group.
2. Set **Visibility timeout (s)**, how long a message stays hidden after a consumer reads it
   (0–43,200, default 30).
3. Set **Message retention**, how long an unconsumed message is kept (1–14 days, default 4).
4. Decide on **Ordered (FIFO) delivery** now. Changing it later destroys the queue and every
   message in it, because each cloud fixes it when the queue is created.

On Hetzner, a queue is a RabbitMQ server in your cluster. Set its **Storage** in GiB (1–256); the
other fields are not shown.

| Cloud | Queue | With ordered delivery |
| --- | --- | --- |
| AWS | SQS | A FIFO queue. The name gains `.fifo`, which counts toward the 80-character limit. Deduplication is by content. The dead-letter queue is FIFO too. |
| GCP | A pull subscription on Pub/Sub | Message ordering on the subscription. All messages for one key must be published from one region. |
| Azure | Service Bus queue | Sessions. They need the Standard or Premium tier: a Basic project is blocked before it deploys. |

### What ordered delivery means

Messages with the same ordering key arrive in the order the service received them. Messages with
different keys have no order between them and are still processed in parallel. A queue whose
messages carry no key is unordered, even with the setting on.

| Cloud | The key | Cost |
| --- | --- | --- |
| AWS | `MessageGroupId` | A higher price per request, and at most 300 messages a second (3,000 batched) |
| GCP | `orderingKey` | At most 1 MB/s per key, and higher latency. A redelivered message makes every later message for its key arrive again. Order is lost in a dead-letter topic. |
| Azure | `SessionId` | One receiver holds a session at a time. A message moved back from the dead-letter queue loses its place. |

On Azure, your consumer must also accept sessions. After you turn sessions on, a client that sends
or receives plain messages stops working.

## Add a topic

1. Select **Add**, then **Topic** in the **Messaging** group.
2. Under **Subscriptions**, add each subscriber: a **Protocol** (**HTTPS**, **Queue**, **Email** or
   **Function**) and its **Endpoint**.

| Cloud | Topic |
| --- | --- |
| AWS | SNS |
| GCP | Pub/Sub topic |
| Azure | Service Bus topic |
| Hetzner | NATS in your cluster |

On Hetzner, Alethia creates the topic but not its subscriptions: a NATS subscriber is a client that
connects, so your application subscribes itself.

Messaging is priced per message, so a plan cannot estimate its cost from the design.

## Check that it worked

After the deploy, the queue's card shows its delivery mode and visibility timeout, and the topic's
card shows its subscription count. Their **Status** tabs show the endpoints.
