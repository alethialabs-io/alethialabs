---
title: Add secrets
description: Create secrets in your cloud's secret store or in a connected store such as HashiCorp Vault, generate their values or set your own, and read them in the cluster.
---

Create secrets for your services. Alethia creates each one in the environment's secret store and
syncs it into the cluster with the External Secrets Operator.

## Before you begin

- To keep secrets outside your cloud, connect a secrets store, such as HashiCorp Vault, as a
  [pluggable connector](/guides/connectors/pluggable).

## Add a secret

1. Select **Add**, then **Secret** in the **Security** group. All secrets on the board collect in
   one card, the vault. Open it to add, find or remove a secret.
2. Enter a name. Use letters, digits and hyphens.
3. Choose how the value is made:
   - Leave **Auto-generate value** on, and set **Length** (8–128) and
     **Include special characters**. Alethia generates the value when it creates the secret.
   - Or turn **Auto-generate value** off to set the value yourself after the deploy.

## Choose where secrets are stored

One environment reads all its secrets through one store.

1. Select the environment's name at the start of the toolbar.
2. On **Settings**, under **Secrets**, choose **Cluster native** (the cloud's secret manager) or a
   connected store. For HashiCorp Vault, set the KV mount path (default `secret`) and KV version
   (`1` or `2`, default `2`).

| Cloud | Cluster native store |
| --- | --- |
| AWS | AWS Secrets Manager |
| GCP | Secret Manager |
| Azure | Key Vault |
| Hetzner | A Vault that Alethia runs in your cluster |

On Hetzner, Hetzner sells no key management service, so the Vault's unseal key is a Kubernetes
Secret in the same cluster. It adds an audit log, leases and revocation, but no protection against
someone with cluster-admin access.

## Set a secret's value

Alethia does not accept a secret's value in the project's settings, because it would be stored in
plain text. Write it in the store instead:

1. Turn **Auto-generate value** off and deploy. On AWS, the secret is created with the placeholder
   value `editme`.
2. Write the real value into the store. On AWS:

   ```bash
   aws secretsmanager put-secret-value \
     --secret-id <secret-name> \
     --secret-string '<value>'
   ```

   With a connected store, write the value there.

A project saved earlier can still hold a value in the AWS template's `value` variable. Alethia keeps
applying it and never shows it. To remove it, open the secret's **Advanced** group and choose
**Remove the stored value**.

## Check that it worked

After the deploy, check that the External Secrets Operator synced the secret:

```bash
kubectl get externalsecrets --all-namespaces
```

Each secret shows `SecretSynced`. A service bound to it reads the value from a Kubernetes Secret.
