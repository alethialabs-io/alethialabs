title: Configure DNS, certificates and a WAF
description: Give an environment a DNS zone, a managed TLS certificate and an in-cluster Let's Encrypt issuer, and put a web application firewall in front of it.
---

Manage the environment's domain, get TLS certificates, and protect it with a web application
firewall (WAF).

## Before you begin

- You own the domain. To use a zone you already have, it is in the project's cloud account, or in
  a connected [Cloudflare connector](/guides/connectors/pluggable).

## Steps

1. Select **Add**, then **DNS** in the **Networking** group. The environment has one DNS card.
2. Leave **Enabled** on.
3. Choose the **DNS provider**: the cluster cloud's own DNS (Route 53, Cloud DNS or Azure DNS), or
   **Cloudflare**. For Cloudflare, also set the zone ID and whether records are proxied. Alethia
   reads the Cloudflare credential at deploy and never stores it in the project.
4. Enter the **Domain name**, such as `example.com`.
5. Optional: in **Existing zone ID**, enter a zone you already own. Leave it empty to create a zone.

   | Cloud | Zone ID looks like |
   | --- | --- |
   | AWS | A public Route 53 hosted zone: `Z1234567890ABC` |
   | GCP | A Cloud DNS managed zone: `projects/…/managedZones/…` |
   | Azure | An Azure DNS zone: `example.com` |

6. Turn on **Managed TLS certificate** to get a certificate for the domain.
7. Turn on **Web application firewall (WAF)** to protect the load balancer.

The certificate and the WAF apply to the cloud's own DNS only, not to Cloudflare.

### Certificates

| Cloud | Issued by | Validation |
| --- | --- | --- |
| AWS | AWS Certificate Manager (ACM) | DNS, through Route 53 |
| GCP | cert-manager in your cluster, from Let's Encrypt | ACME DNS01, through Cloud DNS |
| Azure | cert-manager in your cluster, from Let's Encrypt | ACME DNS01, through Azure DNS |
| Hetzner | Nothing. Bring your own certificate. | — |

Certificates renew before they expire. On AWS the certificate stays in ACM, because an Application
Load Balancer can only use a certificate from ACM or IAM.

On AWS, GCP and Azure the same switch installs cert-manager and creates a `ClusterIssuer` named
`letsencrypt-prod`. Reference it from an Ingress to get a Let's Encrypt certificate for any host in
your zone:

```yaml
metadata:
  annotations:
    cert-manager.io/cluster-issuer: letsencrypt-prod
```

The issuer solves DNS01 challenges, so it works before you have a public ingress and can issue
wildcard certificates. It writes challenge records with the same cloud identity as `external-dns`,
so there is no API key to supply.

### WAF

| Cloud | WAF |
| --- | --- |
| AWS | AWS WAFv2 on the load balancer, with AWS managed rule groups. A CloudFront WAF is available only through `provider_config` (`cloudfront_waf`), for your own distribution. |
| GCP | Cloud Armor at the load balancer |
| Azure | Azure WAF |
| Hetzner | None. Hetzner sells no WAF. |

On Hetzner the canvas still shows both switches, but they create nothing.

## Check that it worked

After the deploy, look up the domain:

```bash
dig +short NS example.com
```

The name servers are your cloud's (or Cloudflare's). With a certificate, `https://` on a host in the
zone answers with a valid certificate.
