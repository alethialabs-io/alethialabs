---
title: Turn on observability
description: Send an environment's cluster metrics, logs and traces to Datadog or Grafana Cloud.
---

Send the cluster's metrics, logs and traces to Datadog or Grafana Cloud. Observability has no
cloud default: you always pick a provider and connect its credential.

## Before you begin

- Connect [Datadog or Grafana Cloud](/guides/connectors/pluggable). Datadog needs an API key and an
  application key. Grafana Cloud needs an instance ID and an API token. Alethia encrypts the
  credential and passes it to the runner at deploy; it is never stored in the project.
- Install the [CLI](/get-started/install-the-cli). The canvas has no observability card yet, so you
  turn it on from the CLI.

## Steps

1. Add the observability component with your provider. For Datadog, set the site (`datadoghq.com`
   by default, or `datadoghq.eu`, `us3.datadoghq.com`, `us5.datadoghq.com`, `ap1.datadoghq.com`):

   ```bash
   alethia project component add --project my-project --kind observability \
     --set enabled=true --set provider=datadog \
     --set 'provider_config={"site":"datadoghq.eu"}'
   ```

   For Grafana Cloud, the remote-write URL is required:

   ```bash
   alethia project component add --project my-project --kind observability \
     --set enabled=true --set provider=grafana \
     --set 'provider_config={"remote_write_url":"https://prometheus-prod-01.grafana.net/api/prom/push"}'
   ```

2. Plan and deploy the environment.

| Provider | Alethia installs |
| --- | --- |
| Datadog | The Datadog agent, with Helm |
| Grafana Cloud | The Grafana Agent, writing metrics to your remote-write URL |

For a metrics stack inside the cluster instead, add the **kube-prometheus-stack**
[add-on](/reference/cli/addons). It installs Prometheus, Grafana and Alertmanager.

## Check that it worked

```bash
alethia project component list --project my-project --kind observability
```

The component shows as enabled. A few minutes after the deploy, the cluster's metrics appear in
Datadog or Grafana Cloud.
