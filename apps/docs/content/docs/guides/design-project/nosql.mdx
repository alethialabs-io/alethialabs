Add a NoSQL table to the environment. You can add as many as you need.

## Before you begin

- You have a project open on the [canvas](/guides/design-project/the-canvas).

## Steps

1. Select **Add**, then **NoSQL table** in the **Data** group.
2. Under **Schema**, set the **Partition key** (default `id`) and its **Key type**.
3. Optional: set a **Sort key** and its **Sort key type**. With the partition key it forms a
   composite key. GCP and Hetzner do not offer a sort key.
4. Under **Capacity**, choose the **Capacity mode**. Only AWS offers more than one.
5. Leave **Point-in-time recovery** on (the default) for continuous backups that you can restore to
   any second in the retention window. It is unavailable on Hetzner, which backs up on a schedule.
6. Optional: under **Replication**, add **Global replica regions**, such as `us-east-1`. Only AWS and
   Azure support them.

| Cloud | Service | Key types | Capacity modes |
| --- | --- | --- | --- |
| AWS | DynamoDB | String, Number, Binary | On-Demand, Provisioned |
| GCP | Firestore | String, Number | Native Mode |
| Azure | Cosmos DB | String, Number | Serverless |
| Hetzner | ScyllaDB in your cluster, with its DynamoDB-compatible API | — | — |

On Azure, replicas apply to the whole Cosmos DB account: it uses every table's list together. The
first replica moves the account from serverless to provisioned billing. On a project that is already
deployed, this replaces the account.

On Hetzner, a client written for DynamoDB works unchanged against the in-cluster table.

NoSQL tables are priced per request, so a plan cannot estimate their cost from the design.

## Check that it worked

After the deploy, the table's card shows a solid dot and its partition key, capacity mode and
point-in-time recovery setting. Its **Status** tab shows the endpoint.
