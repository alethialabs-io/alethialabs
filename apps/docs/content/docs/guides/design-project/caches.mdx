title: Add a cache
description: Add a Redis or Valkey cache to an environment and size it by node type or by memory.
---

Add an in-memory cache to the environment. You can add as many as you need.

## Before you begin

- You have a project open on the [canvas](/guides/design-project/the-canvas).

## Steps

1. Select **Add**, then **Cache** in the **Data** group.
2. Choose the engine. The first cache is named `primary`.

   | Cloud | Engines |
   | --- | --- |
   | AWS | Redis (ElastiCache), Valkey (ElastiCache Serverless) |
   | GCP | Redis or Valkey (Memorystore) |
   | Azure | Redis (Azure Managed Redis) |
   | Hetzner | Valkey, in your cluster |

3. Size the cache in one of two ways:
   - Choose a **Node type**. Each option shows its memory and an approximate monthly price per node.
   - Or set **Memory** in GB (0.5–512). Alethia picks the nearest tier on the project's cloud, so
     the setting survives a move to another cloud.
4. Set **Nodes** (1–6, default 1). On Azure this field is unavailable, because Azure Managed Redis
   is sized by its tier: use **Memory** instead.
5. Optional: turn on **Multi-AZ** to replicate across availability zones, so a replica takes over
   if the primary fails. This adds replica nodes to the cost.
6. Optional: add **Allowed CIDR blocks**, extra networks that can reach the cache. The cluster
   always can. This field is unavailable on Azure, which has no firewall rule for Managed Redis.
7. Optional: under **Advanced**, pin an **Engine version**.

On Hetzner, set **Storage**, the volume per Valkey node in GiB (1–512). It defaults to the memory
size. **Node type**, **Memory** and **Multi-AZ** are not shown there.

### Node types

| Cloud | Types (memory) | Default |
| --- | --- | --- |
| AWS | `cache.t3.micro` (0.5 GB), `cache.t3.small` (1.37 GB), `cache.t3.medium` (3.09 GB), `cache.r6g.large` (13.07 GB), `cache.r6g.xlarge` (26.32 GB) | `cache.t3.medium` |
| GCP | `M1` (1 GB), `M2` (4 GB), `M3` (10 GB), `M4` (35 GB) | `M1` |
| Azure | `Balanced_B0` (0.5 GB), `Balanced_B1` (1 GB), `Balanced_B3` (3 GB), `Balanced_B5` (6 GB), `Balanced_B10` (12 GB), `Balanced_B20` (24 GB) | `Balanced_B1` |
| Hetzner | 1, 2 or 4 GiB | 1 GiB |

## Check that it worked

After the deploy, open the cache's **Status** tab. **Endpoints** shows the primary endpoint, and a
reader endpoint when Multi-AZ is on. Redis and Valkey listen on port 6379.
