---
title: Configure the network
description: Create a new VPC or VNet for an environment, or deploy into a network that already exists in your cloud account.
---

Give the environment a new network, or attach it to one that already exists in your account.

## Before you begin

- The project's cloud account is connected. To use an existing network, it must be in the
  project's region and show in the account's [asset inventory](/concepts/connection-health).

## Open the network settings

1. On the [canvas](/guides/design-project/the-canvas), select the environment's name at the start
   of the toolbar.
2. On **Settings**, find **Network (VPC)**.

## Create a new network

1. Leave **Provision a new network** on.
2. Set **CIDR block**. The default is `10.0.0.0/16`. Each cloud carves subnets out of this range, so
   it must be at least this wide:

   | Cloud | Widest prefix allowed |
   | --- | --- |
   | AWS, Azure | `/18` |
   | Hetzner | `/22` |
   | GCP | Any valid IPv4 CIDR |

3. Choose the NAT gateway. **Single NAT gateway** is on by default: one shared NAT, which costs
   less. Turn it off for one NAT per availability zone. On AWS, one NAT costs about $35 a month and
   three cost about $105.
4. Optional: add **Allowed CIDR blocks**, the extra networks that can reach resources in this
   network.

| Cloud | What Alethia creates |
| --- | --- |
| AWS | A VPC with public and private subnets across availability zones, an internet gateway, NAT gateways and route tables |
| GCP | A VPC network with custom-mode subnets in the region, and Cloud NAT with a Cloud Router |
| Azure | A VNet with subnets for nodes and services, a NAT gateway and network security groups |

## Use an existing network

On AWS, GCP and Azure you can deploy into a network you already have:

1. Turn off **Provision a new network**.
2. Choose the network under **Existing network**. The list comes from the asset inventory, which
   updates itself.

At deploy, the runner does not create a network. The template reads yours and puts the cluster in
it:

| Cloud | What the template uses |
| --- | --- |
| AWS | The VPC's subnets, split into public and private |
| GCP | The VPC network's subnetwork in the project's region, with its secondary ranges for pods and services |
| Azure | One of the VNet's subnets, for AKS |

The network is the only resource you can reuse this way, because the cluster attaches into it. A
database, cache or bucket that already exists is not something to provision: give your service its
endpoint and credentials instead.

## Check that it worked

Run a plan from the review view. It lists the network resources to create. With an existing
network, it creates none.
