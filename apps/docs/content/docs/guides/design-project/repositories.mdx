Name the Git repository that ArgoCD syncs your manifests from. It is optional: without one, the
environment still gets ArgoCD, but ArgoCD runs none of your applications. How the sync behaves, what
Alethia commits back, and what your manifests may create are in
[The apps repository](/concepts/apps-repository).

## Before you begin

- Connect the repository's [Git provider](/guides/connectors/git-providers): GitHub, GitLab or
  Bitbucket. A public `https://` repository also works without a connection. An `ssh://` or
  `git@host:path` repository always needs one.
- To run [marketplace add-ons in GitOps mode](/concepts/apps-repository#which-git-providers-support-gitops-mode),
  the repository is on GitHub.

## Lay out the repository

ArgoCD syncs one directory of your repository's default branch: the repository root, or the
overlay path you set.

| Path | What it holds |
| --- | --- |
| The synced directory | Your manifests, directly in it: ArgoCD does not read subdirectories of a plain directory. A Kustomize or Helm source there reads its own subdirectories. |
| `addons/` | The add-ons you run in GitOps mode. Alethia creates it. Create it empty to avoid an ArgoCD error before then. |
| `overlays/<name>/` | Optional. With no overlay path set, each one becomes its own Application, `apps-<name>`. |

To start from a working layout, copy the
[apps starter template](/guides/design-project/starter-templates).

## Steps

1. On the [canvas](/guides/design-project/the-canvas), select **Add**, then **Repository** in the
   **DevOps** group.
2. Choose the **ArgoCD apps repository**.
3. Optional: set **Overlay path**, the directory this environment syncs, such as `overlays/dev`.
   Leave it empty to sync the repository root.
4. Review the plan and deploy.

Use an overlay path when several environments share one repository: `overlays/dev` for development,
`overlays/prod` for production. Setting one turns overlay discovery off for this environment, so it
does not also take over the directories other environments deliver.

The path must:

| Rule | Accepted | Refused |
| --- | --- | --- |
| Be empty or `.` for the root, or relative to the root | `overlays/dev` | `/overlays/dev` |
| Be normalized | `overlays/dev` | `../shared`, `overlays//dev`, `overlays/dev/` |
| Have segments that start with a letter or digit, then letters, digits, `.`, `_` or `-` | `env-1.2_a` | `overlays/$env` |
| Be at most 512 characters | | |

A path that breaks a rule is refused, never corrected.

<Callout type="warn">
Anyone who can push to the default branch can change what runs: a commit there deploys without an
Alethia deploy or an approval. Protect the branch if that is not what you want.
</Callout>

## Check that it worked

After the deploy, the `apps` Application in ArgoCD is **Synced** and **Healthy**, and your
resources exist:

```bash
kubectl get applications -n argocd
```

If the deploy succeeded but the cluster is empty, see
[Troubleshoot design and GitOps](/troubleshooting/design-project#the-deploy-succeeded-but-the-cluster-is-empty).
