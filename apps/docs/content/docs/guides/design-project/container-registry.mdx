---
title: Add a container registry
description: Create private image repositories in your cloud's registry or in Docker Hub, with immutable tags and vulnerability scanning.
---

Create a private repository for your container images. You can add as many as you need, for
example one each for `api`, `frontend` and `worker`.

## Before you begin

- To use Docker Hub instead of your cloud's registry, connect it as a
  [pluggable connector](/guides/connectors/pluggable), with a username and an access token.

## Add a repository

1. Select **Add**, then **Container registry** in the **DevOps** group.
2. Enter a name, such as `api`.
3. Turn on **Immutable tags** to stop a pushed tag from being overwritten. Use it in production, so
   a tag such as `v1.2.3` always points to the same image.
4. Turn on **Vulnerability scanning** to scan each pushed image for known CVEs.

## Choose the registry

One environment pushes and pulls through one registry.

1. Select the environment's name at the start of the toolbar.
2. On **Settings**, under **Container registry**, choose **Cloud native** or Docker Hub. For Docker
   Hub, you can set a namespace or organization; it defaults to the username.

| Registry | What Alethia creates |
| --- | --- |
| AWS | ECR repositories |
| GCP | Artifact Registry repositories |
| Azure | ACR repositories |
| Hetzner | A Harbor registry in your cluster, with a scoped robot account for pulls |
| Docker Hub | No repository. Alethia adds an `imagePullSecret` so workloads can pull from Docker Hub. **Immutable tags** and **Vulnerability scanning** are not shown. |

On AWS, GCP and Azure, nodes pull from the project's registry with their own cloud identity, so no
pull secret is needed.

## Check that it worked

After the deploy, open the registry's **Status** tab. **Endpoints** shows the repository URL, such
as `123456789012.dkr.ecr.eu-west-1.amazonaws.com/api`. Push an image to it:

```bash
docker push 123456789012.dkr.ecr.eu-west-1.amazonaws.com/api:v1.0.0
```
