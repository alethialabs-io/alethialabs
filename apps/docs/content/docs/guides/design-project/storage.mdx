# Object Storage

A **bucket** is a first-class node on the [architecture canvas](/guides/design-project/the-canvas) — the same standing as a database, cache, or container registry. Add one from the palette's **Storage** group to provision object storage for files and assets. Multiple buckets can be added per project.

Each bucket is scoped to the project's cloud account and environment. Its name is unique per project, per environment.

## Fields Per Bucket

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| **Name** | Text input | `assets` | Bucket name (S3-safe — see [Naming rules](#naming-rules)) |
| **Versioning** | Toggle | Off | Keep every version of an object; restore or roll back at any time (on Azure this applies to the whole project — see [Azure](#azure)) |
| **Encryption at rest** | Toggle | On | Server-side encryption with the cloud's managed keys |
| **Public access** | Toggle | Off (private) | Allow unauthenticated reads (static assets); off keeps the bucket private |
| **CORS origins** | Text | Empty | Comma-separated browser origins, such as `https://app.example.com`, that may read and write objects (`GET`, `PUT`, `POST`). On Azure, this applies to the whole storage account — see [Azure](#azure) |

The name, versioning, and encryption fields are grouped under **General**; public access and CORS origins are grouped under **Access**.

## Naming rules

Bucket names use the strictest cloud rules, so one name works on every provider:

- 3–63 characters.
- Lowercase letters, digits, and hyphens only.
- Must start and end with a letter or digit (no leading or trailing hyphen).

The name field lowercases input and strips disallowed characters as you type; the full rule is validated on save.

<Callout type="info">
A single S3-safe name is portable across AWS, GCP, Azure, Alibaba Cloud, and Hetzner, so a bucket you design on one provider provisions unchanged on another.
</Callout>

## Backing service by provider

Buckets are supported on every provider. The name and toggles map to each cloud's object-storage service:

| Provider | Service |
|----------|---------|
| **AWS** | S3 |
| **GCP** | Cloud Storage |
| **Azure** | Blob Storage |
| **Alibaba Cloud** | OSS |
| **Hetzner** | MinIO (Object Storage) |

### Hetzner

Compute-only Hetzner projects provision buckets natively via Object Storage (the `aminueza/minio` OpenTofu provider). Two fields differ on Hetzner:

- **Encryption at rest** is not shown — Hetzner Object Storage always encrypts at rest, so there is no per-bucket toggle.
- **CORS origins** is not shown — the provider does not apply CORS to Hetzner's S3 backend.

### Azure

Some fields behave differently on Azure. An Azure project has one storage account, which holds every bucket in the project, and Blob Storage puts some settings on that account rather than on the container.

- **Versioning** is an account setting. Turning it on for one bucket versions **every** bucket in that project. Leaving it on for a bucket that no longer needs it costs storage; the alternative — ignoring a bucket that asks for it — loses data on the first overwrite, so Alethia turns versioning on for the account whenever any bucket asks for it.
- **Public access** is applied per bucket, as it is everywhere else. The account permission that allows public containers is opened only when at least one bucket asks for public access, and stays closed otherwise.
- **CORS origins** is an account setting. The storage account has one CORS rule, and it allows every origin that any bucket in the project lists. An origin that you allow on one bucket can therefore also call the other buckets in that project. When no bucket lists an origin, the account has no CORS rule.
  - Each origin must be `*` or a scheme, a host and an optional port, such as `https://app.example.com` or `http://localhost:3000`. A path, a trailing slash, a missing scheme or a scheme other than `http` or `https` is refused when the project is planned.
  - `*` allows every origin to read and write **every** bucket in the project, because the rule belongs to the account.
  - Azure allows at most 64 origins on the rule. The limit counts the distinct origins of all buckets together.

### Google Cloud

**Public access** on Google Cloud does two things: it stops Cloud Storage from refusing public grants on that bucket, and it grants read access to everyone. Uniform bucket-level access stays on for every bucket regardless — it controls per-object ACLs, not public reads, and Cloud Storage will not let it be turned off again once a bucket has had it for 90 days.

<Callout type="warn">
Many Google Cloud organizations set the `constraints/iam.allowedPolicyMemberDomains` organization policy, which blocks public grants everywhere in the organization. Under that policy a public bucket is refused when the project is deployed, and the deployment says so rather than failing part-way through.
</Callout>

## Cloud placement

A bucket inherits the project's cloud account and region. When left unset, its per-resource cloud identity and region fall back to the project's own — so a bucket lands in the same account and region as the rest of the project unless it is placed on another connected account.

## On the canvas

The bucket card summarizes its configuration without opening the inspector:

- **Access** — `public` or `private`.
- **Versioning** — `on` or `off`.
- **CORS** — the number of allowed origins, or `none`.

## After provisioning

Each bucket carries a lifecycle status — `PENDING`, `CREATING`, `ACTIVE`, `UPDATING`, `FAILED`, `DESTROYING`, or `DESTROYED` — and an estimated monthly cost that rolls up into the [cost sidebar](/guides/design-project/cost-sidebar).
