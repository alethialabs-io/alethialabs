---
title: Add a bucket
description: Add an object storage bucket to an environment, with versioning, encryption, public access and CORS origins, on any cloud.
---

Add a bucket for files and assets. You can add as many as you need, and each name is unique in
the environment.

## Before you begin

- You have a project open on the [canvas](/guides/design-project/the-canvas).

## Steps

1. Select **Add**, then **Bucket** in the **Storage** group.
2. Enter a name (default `assets`). It must be 3–63 characters of lowercase letters, digits and
   hyphens, and start and end with a letter or digit. These are the strictest cloud rules, so the
   name works on every cloud. The field lowercases what you type and drops other characters.
3. Under **General**:
   - Turn on **Versioning** to keep every version of an object.
   - Leave **Encryption at rest** on (the default) for server-side encryption with the cloud's keys.
4. Under **Access**:
   - Leave **Public access** off to keep the bucket private. Turn it on to allow reads without
     authentication, for static assets.
   - Optional: add **CORS origins**, separated by commas, such as `https://app.example.com`. They
     can read and write objects (`GET`, `PUT`, `POST`) from a browser.

The bucket uses the project's cloud account and region unless you place it on another connected
account.

| Cloud | Service |
| --- | --- |
| AWS | S3 |
| GCP | Cloud Storage |
| Azure | Blob Storage |
| Hetzner | Hetzner Object Storage |

### Differences between clouds

**Hetzner** always encrypts at rest, so **Encryption at rest** is not shown. **CORS origins** is not
shown either, because the provider does not apply CORS there.

**Azure** keeps every bucket of a project in one storage account, and some settings belong to the
account:

- **Versioning** on any bucket turns it on for every bucket in the project.
- **CORS origins** form one rule for the account, made of every bucket's origins. An origin allowed
  on one bucket can call every bucket. `*` allows every origin on every bucket. The rule holds at
  most 64 distinct origins.
- Each origin is `*`, or a scheme, a host and an optional port, such as `http://localhost:3000`. A
  path, a trailing slash, or a scheme other than `http` or `https` fails the plan.
- **Public access** is set per bucket. The account allows public containers only while at least
  one bucket asks for it.

**GCP**: **Public access** lets the bucket accept public grants and gives everyone read access.
Uniform bucket-level access stays on for every bucket. An organization policy
`constraints/iam.allowedPolicyMemberDomains` blocks public grants: under it, the deploy refuses a
public bucket and says why.

## Check that it worked

The bucket's card shows its access (`public` or `private`), versioning (`on` or `off`) and the
number of CORS origins. After the deploy, its **Status** tab shows the endpoint.
