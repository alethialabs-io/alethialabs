---
title: Connect a Git provider
description: Connect GitHub, GitLab or Bitbucket over OAuth so that Alethia can list your repositories and ArgoCD can deploy from them.
---

Connect a Git provider so that Alethia can list your repositories and ArgoCD can watch them. All
three providers connect over OAuth, and Alethia refreshes the token for you.

## Before you begin

- You have an account on GitHub, GitLab or Bitbucket that can read the repositories you deploy.
- This console has an OAuth app for the provider. If it does not, the card reads
  **Not enabled on this instance**. A self-hosted console sets this up in
  [Configuration](/self-host/configuration).

## Steps

1. Open **Connectors** and find the provider under **Source**.
2. Select **Connect**.
3. On the provider's page, approve access. GitHub asks for the `repo` scope.

The provider sends you back to **Connectors**.

## What the token is used for

| Use | Detail |
| --- | --- |
| Repository lists | The project form and the canvas list repositories from the provider. |
| GitOps | ArgoCD reads your repositories with the token and syncs changes. |
| Templates | Alethia can read infrastructure templates from your repositories. |

When the access token expires, Alethia uses the stored refresh token to get a new one the next time
it needs the provider. If that fails, the card reads **Needs reconnection**: select **Reconnect**.

## Check that it worked

The card reads **Connected**, and the repository picker in a project lists your repositories.

## Disconnect a Git provider

Select **Manage** on the card, then **Disconnect**. Alethia deletes the stored tokens.

<Callout type="warn">
Every project that deploys from this provider loses repository access. ArgoCD shows its sync as
failed until you connect the provider again.
</Callout>
