---
title: Connectors
description: Connect the cloud accounts, Git providers and third-party tools that your projects provision into and read from.
---

Connect the accounts that Alethia needs before your first deploy: one cloud account and one Git
provider. Other connectors are optional. They let a project use a tool you already run instead of
the cloud's own service.

## Before you begin

- Your role can manage connections (`manage_identities`). Connections belong to the organization,
  and every member sees them.

## Choose what to connect

| Group on the Connectors page | Providers | How it signs in | Guide |
| --- | --- | --- | --- |
| **Clouds** | AWS, GCP, Azure | Keyless: a short-lived token from the Alethia OIDC issuer. Alethia stores no key. | [AWS](/guides/connectors/aws), [GCP](/guides/connectors/gcp), [Azure](/guides/connectors/azure) |
| **Clouds** | Hetzner | A project-scoped API token, encrypted at rest and revocable. | [Hetzner](/guides/connectors/hetzner) |
| **Source** | GitHub, GitLab, Bitbucket | OAuth | [Git providers](/guides/connectors/git-providers) |
| **Registries**, **Secrets**, **Observability**, **DNS** | Docker Hub, HashiCorp Vault, Datadog, Cloudflare and others | API key or token, encrypted at rest | [Pluggable connectors](/guides/connectors/pluggable) |
| **Chart Repos** | Private Helm and OCI chart sources | Username and token, encrypted at rest | [Chart repositories](/guides/connectors/chart-repositories) |
| **Secrets** | A cloud secret manager in another account | A read-only grant in that account | [Cross-account secret managers](/guides/connectors/cross-account-secret-managers) |

## Steps

1. Open **Connectors**.
2. Find the provider. Filter by group or status, or search by name.
3. Select **Connect** on its card, and follow the provider's guide.

Each cloud account you connect becomes a **cloud identity**: the account that projects provision
into. A provider can hold several accounts. See
[Manage connections](/guides/connectors/managing-connections).

## Check that it worked

The card shows its state:

| State | Meaning |
| --- | --- |
| **Connected** | The credential works. |
| **Limited permissions** | A cloud account signs in, but some permissions are missing. |
| **Verification failed** | A cloud account cannot sign in. |
| **Needs reconnection** | A Git token expired and could not be refreshed. Select **Reconnect**. |
| **Not connected** | Nothing is stored. |
| **Coming soon** | The provider is listed but cannot be connected yet. |
| **Not enabled on this instance** | This console lacks the setup that the provider needs. |
