---
title: Connect an Azure subscription
description: Connect an Azure subscription with a user-assigned managed identity that trusts the Alethia OIDC issuer. No client secret and no app registration.
---

Connect an Azure subscription so that Alethia can provision into it. You create a managed identity
in your own subscription. Alethia signs in as that identity with a short-lived token, so there is
no client secret.

## Before you begin

- You can create managed identities, custom roles and role assignments in the subscription. You do
  not need directory-admin rights, and no app registration is made.
- Your Alethia role can manage connections (`manage_identities`).
- You know the subscription ID (Azure Portal → **Subscriptions**).

## Steps

The **Azure CLI** and **Terraform / IaC** tabs create the same resources.

<Tabs items={["Azure CLI", "Terraform / IaC"]}>
  <Tab value="Azure CLI">
    <Steps>

    ### Open the connect sheet
    In the console, open **Connectors**, select **Microsoft Azure**, then select **Connect**. Enter
    the **Subscription ID** and choose **Azure CLI**.

    ### Run the setup in Azure Cloud Shell
    Select **Open Cloud Shell** and paste the command from the sheet. It already names your
    subscription.

    ### Enter the IDs it prints
    Enter the **Tenant ID** and **Client ID**, then select **Connect**.

    </Steps>
  </Tab>
  <Tab value="Terraform / IaC">
    <Steps>

    ### Open the connect sheet
    In the console, open **Connectors**, select **Microsoft Azure**, then select **Connect**. Enter
    the **Subscription ID** and choose **Terraform / IaC**.

    ### Apply the module
    Download the module from the sheet and apply it with `tofu apply` or `terraform apply`.

    ### Enter the tenant_id and client_id outputs
    Enter them in **Tenant ID** and **Client ID**, then select **Connect**.

    </Steps>
  </Tab>
</Tabs>

To connect from a terminal, run `alethia connector azure --subscription <id>`. To submit an identity
you already made, add `--tenant-id` and `--client-id`. See
[`alethia connector azure`](/reference/cli/connector#alethia-connector-azure).

## What the setup creates

| Resource | Detail |
| --- | --- |
| User-assigned managed identity | A plain ARM resource in your subscription. |
| Federated identity credential | Trusts the Alethia issuer for subject `alethia-connector` and audience `api://AzureADTokenExchange`. |
| **Alethia Provisioner** custom role | Lists only the actions the project templates need, instead of `Contributor`. |

### Assign the least-privilege role

The setup assigns the **Alethia Provisioner** role to the identity. The role covers resource
groups, AKS, virtual networks, PostgreSQL Flexible Server, Redis Cache, DNS zones, Container
Registry, Key Vault, Storage, Service Bus, Cosmos DB, WAF policies, and the managed identities of
in-cluster workloads.

Its one escalation-grade permission, `roleAssignments/write`, has an ABAC condition. It can assign
only the **DNS Zone Contributor** role, so the identity cannot make itself Owner. Details are in
[Security](/concepts/security#per-cloud).

## Check that it worked

When you select **Connect**, the console signs in as the managed identity and runs an ARM read
call. No runner is involved. The account then shows **Connected**, **Limited permissions** (missing
permissions are listed), or **Verification failed**. To fix a failed check, see
[Troubleshoot: connect a cloud](/troubleshooting/connect).

## Stop Alethia's access

Delete the managed identity or its role assignment. Alethia stores only the tenant ID, the
subscription ID and the identity's client ID, which are all public identifiers.
