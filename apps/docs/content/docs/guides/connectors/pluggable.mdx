title: Connect a DNS, secrets, registry or observability tool
description: Connect Cloudflare, HashiCorp Vault, Docker Hub, Datadog and other tools with an API key, so a project uses them instead of the cloud's own service.
---

Connect a tool you already run, so that a project uses it instead of the cloud's own service. For
example, Cloudflare instead of Route 53, or Vault instead of AWS Secrets Manager. These connectors
sign in with an API key or token.

## Before you begin

- Your role can manage connections (`manage_identities`).
- You have an API credential for the tool, with the permission listed below.

## Providers

| Group | Provider | Credential | Settings |
| --- | --- | --- | --- |
| **DNS** | Cloudflare | API Token (Zone:DNS:Edit) | Zone ID, Proxy records through Cloudflare |
| **Secrets** | HashiCorp Vault | Vault Address, Vault Token | KV Mount Path, KV Version |
| **Secrets** | Generic (Vault-compatible) | Endpoint Address, API Token | KV Mount Path, KV Version |
| **Secrets** | Doppler | API Token | Project, Config |
| **Secrets** | Infisical | Machine Identity Client ID and Client Secret | Host, Workspace ID, Project Slug, Environment, Folder Path |
| **Secrets** | 1Password | Service Account Token | Vault UUID |
| **Registries** | Docker Hub | Username, Access Token | Namespace / Organization |
| **Registries** | GitHub Container Registry | Username, Personal Access Token | — |
| **Registries** | GitHub Enterprise Container Registry | Username, Personal Access Token | Registry URL |
| **Registries** | GitLab Container Registry | Username, Token | Registry URL |
| **Registries** | Quay, Harbor, Generic Registry | Username, password or token | Registry URL |
| **Registries** | DigitalOcean Container Registry | API Token | — |
| **Registries** | Scaleway Container Registry | Secret Key | Registry URL |
| **Observability** | Datadog | API Key, Application Key | Datadog Site |
| **Observability** | Grafana Cloud | Instance ID / Username, API Token | Remote Write URL |

Private Helm chart sources are a separate group: see
[Chart repositories](/guides/connectors/chart-repositories). Cloud registries and secret managers in
another cloud account are listed as **Coming soon**; see
[Cross-account secret managers](/guides/connectors/cross-account-secret-managers).

## Steps

<Steps>

### Connect the provider
Open **Connectors**, find the provider, and select **Connect**.

### Enter the credential
Fill in the fields from the table. Alethia encrypts secret fields with AES-256-GCM. It stores
non-secret fields, such as a Vault address or a username, as they are.

### Check the credential
Alethia calls the provider's API to check the credential, for example Cloudflare's token check or
a Docker Hub sign-in. A credential that fails the check is still saved, so you can fix it and try
again.

### Use it in a project
On the canvas, pick the provider for the component:
[DNS](/guides/design-project/dns), [Secrets](/guides/design-project/secrets),
[Container registry](/guides/design-project/container-registry) or
[Observability](/guides/design-project/observability).

</Steps>

When the project deploys, the runner adds the provider's module to the plan and leaves out the
cloud's own resource for that component. Observability has no cloud default, so it only adds.

## How the credential reaches the runner

Secret fields are never written into a project's configuration snapshot. The console decrypts them
only when a runner claims a job that needs them, and hands them to that runner. A self-hosted
console sets the encryption key in `ALETHIA_CRED_ENCRYPTION_KEY`; see
[Configuration](/self-host/configuration).

## Check that it worked

The card reads **Connected**, and the provider appears as a choice in the component on the canvas.
