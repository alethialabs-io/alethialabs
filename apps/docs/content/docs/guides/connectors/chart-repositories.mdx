title: Connect a private chart repository
description: Connect a private Helm or OCI chart source so that Alethia can scan the charts it holds and ArgoCD can pull them.
---

Connect a private chart source so that Alethia can scan your Helm charts and ArgoCD can pull them.
Public charts, including every add-on in the marketplace, need no connector.

A chart repository credential is not a container registry credential. A
[container registry](/guides/design-project/container-registry) credential lets your workloads pull
images. A chart repository credential lets Alethia and ArgoCD read charts. One does not do the job
of the other.

## Before you begin

- Your role can manage connections (`manage_identities`).
- You have a username and a token that can read the charts.

## Providers

| Provider | Registry host | Credential |
| --- | --- | --- |
| HTTPS Helm Repository | The full repository URL, which you give | Username, password or token |
| GitHub Container Registry (OCI Helm) | `ghcr.io` | Username, password or token |
| Docker Hub (OCI Helm) | `registry-1.docker.io` | Username, access token |
| GitLab Container Registry (OCI Helm) | `registry.gitlab.com`, or your own host | Username, password or token |
| Scaleway Container Registry (OCI Helm) | Your Scaleway host, for example `rg.fr-par.scw.cloud` | Secret key |
| Generic OCI Registry (Helm) | Your host, for example Harbor or JFrog | Username, password or token |

Amazon ECR and ECR Public are listed as **Coming soon**. An ECR token expires after 12 hours, so
there is no stable password to store.

## Steps

<Steps>

### Connect the provider
Open **Connectors**, find the provider under **Chart Repos**, select **Connect**, and enter the
credential.

### Add a chart repository to the environment
On the canvas, select **Add → DevOps → Chart repository**, and pick the connected provider. Each
environment has its own, so staging and production can read from different registries.

### Give the host
GitHub Container Registry and Docker Hub need nothing more. For a self-hosted or generic registry,
give the bare host, such as `registry.acme.io`, with no scheme and no path. For an HTTPS Helm
repository, give the full `https://` URL.

### Attach the private chart
Select **Add → Bring your own Helm chart**, choose **OCI registry**, and give the full reference with
the chart name, such as `oci://ghcr.io/acme/payments`, and a version (`*` for the latest). The dialog
tells you whether a chart repository on the environment covers that host.

### Deploy
Before it syncs any chart, the runner writes an ArgoCD repository credential for the repository.

</Steps>

## How Alethia matches a chart to a credential

Alethia picks the credential from the chart's host, and takes the most specific match:

- An OCI chart matches by URL prefix. A credential for `oci://ghcr.io` covers
  `oci://ghcr.io/acme/charts/payments`.
- An HTTPS chart repository must match exactly.

ArgoCD uses the same rule. So one credential serves both the
[safety scan](/guides/design-project/bring-your-own-charts#the-safety-scan) when you attach a chart
and ArgoCD's pull at deploy time. A chart whose host matches nothing is read without a credential:
that works for a public chart and fails with an authentication error for a private one.

The token is the only secret. The repository URL and host are stored as configuration and appear in
the project's configuration snapshot. The token reaches the runner when it claims the job, and is
never written into the configuration, the job record or the job logs.

## Registries on a private network

By default, the runner refuses to pull a chart from a private or link-local address, so that a chart
URL cannot reach internal services or the cloud metadata service. If your registry is on an internal
network, such as a self-hosted Harbor on RFC 1918 addresses, set
`ALETHIA_HELM_REGISTRY_ALLOW_PRIVATE=1` on the runner. See
[Self-operated runners](/guides/runners/self-operated#environment-variables). Loopback and
link-local addresses stay blocked.

## Check that it worked

The chart dialog says the environment's chart repository covers the chart's host, and the safety
scan finishes without an authentication error.
