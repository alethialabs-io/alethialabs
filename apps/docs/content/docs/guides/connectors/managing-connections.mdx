---
title: Manage connections
description: Add a second account to a cloud, re-verify a connection, rename an account, or disconnect one, from the connector's detail sheet.
---

Change a cloud connection after you made it: add another account, check it again, rename it, or
remove it. To connect a cloud for the first time, see [Connectors](/guides/connectors).

## Before you begin

- Your role can manage connections (`manage_identities`). Without it, you see the same controls,
  disabled, with the reason.
- Connections belong to the organization. Every member sees them.

## Open the detail sheet

1. Open **Connectors**.
2. Select **Manage** on the provider's card.

The sheet lists every account you connected to that provider, including one that failed to
verify, with its state and three buttons: **Re-verify**, **Rename** and **Disconnect**. These
actions run in the console. No runner or job is involved.

## Add another account

Connect a second AWS account, GCP project or Azure subscription to the same provider.

1. In the detail sheet, select **Add another account**.
2. Complete the provider's connect flow: [AWS](/guides/connectors/aws), [GCP](/guides/connectors/gcp),
   [Azure](/guides/connectors/azure) or [Hetzner](/guides/connectors/hetzner).

The new account gets its own row. It does not replace the existing one. If this console no longer
offers new connections for the cloud, the button is missing and the sheet says why. Existing
accounts keep their buttons.

## Re-verify a connection

Check an account again with its stored configuration, for example after you changed its role or
policy in the cloud.

1. In the detail sheet, find the account.
2. Select **Re-verify**.

The account shows **Verifying…**, then one of these states:

| State | Meaning |
| --- | --- |
| **Connected** | Alethia can sign in and has the permissions it checks for. |
| **Limited permissions** | Alethia can sign in, but some permissions are missing. They are listed. |
| **Verification failed** | Alethia cannot sign in. The reason is shown. |

## Rename an account

Replace a default name such as `AWS Account (123456789012)` with one people recognize.

1. In the detail sheet, find the account.
2. Select **Rename**, type the name, and select **Save name**.

The name changes nothing else.

## Disconnect an account

Remove Alethia's access to one account. Other accounts on the same provider are not changed.

1. In the detail sheet, find the account.
2. Select **Disconnect**.
3. The dialog lists the projects that use the account. Type the account's name to confirm.

Disconnecting:

- deletes the account's stored credentials,
- unlinks every project that used the account, so those projects cannot provision until you pick
  another account,
- deletes the account's [asset inventory](/concepts/connection-health#asset-inventory).

The trust you created in the cloud stays. To end access on the cloud side too, delete the role,
pool, managed identity or token there.

To disconnect a Git provider or a pluggable connector, select **Disconnect** at the bottom of its
sheet. From the CLI, run `alethia connector remove <provider|cloud-identity-id>`.

## Check that it worked

The account's row shows its new state or name, or is gone from the sheet. `alethia connector list`
prints the same list.
