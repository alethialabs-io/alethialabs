# DNS & WAF

The DNS section is optional (controlled by a master toggle). When enabled, it configures domain management, SSL/TLS certificates, and web application firewall protection.

## Fields

| Field | Type | Description |
|-------|------|-------------|
| **Enabled** | Toggle | Master switch for DNS configuration |
| **DNS Provider** | Select | Cloud-native (Route 53 / Cloud DNS / Azure DNS) or a [pluggable connector](/console/connectors/pluggable) |
| **Zone ID** | Select or text | Existing DNS hosted zone |
| **Domain Name** | Text input | Auto-filled from zone, or manually entered |
| **Managed Certificate** | Toggle | Auto-provision SSL/TLS certificate (cloud-native only) |
| **WAF Options** | Toggles | Provider-specific WAF configuration (cloud-native only) |

## DNS Provider

The **DNS Provider** selector decouples *what* the Project needs (a managed zone) from *who* provides it:

- **Cloud-native** (default) — uses the cluster cloud's DNS service; the managed-certificate and WAF toggles apply.
- **Cloudflare** — manages records on Cloudflare instead. Requires a connected [Cloudflare connector](/console/connectors/pluggable); set the **Zone ID** and the **Proxied** option (orange-cloud). The cloud-native DNS/cert resources are skipped at provision time.

When a pluggable provider is selected, its credential is pulled from `connector_credentials` on the runner at provision time — never stored in the Project.

## Managed Certificates

When enabled, the platform provisions a TLS certificate automatically:

| Provider | Issued by | Validation |
|----------|-----------|------------|
| AWS | ACM (AWS Certificate Manager) | DNS validation via Route 53 |
| GCP | cert-manager, in your cluster | ACME DNS01 via Cloud DNS |
| Azure | cert-manager, in your cluster | ACME DNS01 via Azure DNS |
| Alibaba | Not available — bring your own | — |
| Hetzner | Not available — bring your own | — |

Certificates are renewed automatically before expiration.

On **GCP and Azure** the certificate is a free Let's Encrypt one, issued and renewed inside your
cluster by cert-manager and served by the cloud's own ingress — the GKE Ingress reads it from a
Kubernetes Secret, and the Application Gateway has it lifted onto its listener by AGIC. Neither
cloud provisions a cloud-native certificate any more.

On **AWS** the certificate stays in ACM. That is not an oversight: an Application Load Balancer can
only reference a certificate by ARN in ACM or IAM, and ACM will not bind a certificate whose private
key it never held — so a cert-manager certificate cannot terminate an ALB at all. ACM is free and
renews itself, so nothing is lost by it.

On **Alibaba and Hetzner** nothing issues a certificate. The alicloud provider can only upload one
you already hold, and cert-manager ships no DNS01 solver for either cloud's DNS. Bring your own.

### In-cluster certificates

On AWS, GCP and Azure the same toggle also installs `cert-manager` in the cluster and creates a
`ClusterIssuer` named `letsencrypt-prod`. Reference it from an Ingress to get a Let's Encrypt
certificate for any hostname in your zone:

```yaml
metadata:
  annotations:
    cert-manager.io/cluster-issuer: letsencrypt-prod
```

The issuer solves ACME **DNS01** challenges, so it works before you have a public ingress, and it
can issue wildcard certificates. It writes its challenge records with the same cloud identity
`external-dns` uses, so there is no API key to supply.

<Callout type="warn">
Not available on Alibaba Cloud or Hetzner. `cert-manager` ships no DNS01 solver for either DNS
service, so Alethia creates no issuer rather than one whose challenges never complete. Bring your
own certificate on those clouds. The deploy records the skip and its reason with the environment's
other infrastructure-service decisions.
</Callout>

## Web Application Firewall

WAF protects web applications from common attacks (SQL injection, XSS, bot traffic).

Alethia provisions a WAF on AWS, Google Cloud and Azure only. On Alibaba Cloud the switch is disabled and
says why: WAF 3.0 is an account-level purchase there, so a project that owned one would release the whole
account's firewall when it was destroyed. Buy a WAF 3.0 instance in your own account instead and put it in
front of your ingress from the WAF console. Hetzner sells no web application firewall at all.
