# Runner Commands

Runners execute infrastructure jobs. Manage them with `alethia runner`.

## `alethia runner deploy`

Deploy a new runner to an AWS account. Creates a runner record and queues a
`DEPLOY_RUNNER` job using the latest stable release.

```bash
alethia runner deploy --cloud-identity-id <id> --name <name> --region <region>
```

| Flag | Description |
|------|-------------|
| `--cloud-identity-id` | Cloud identity to deploy into (AWS only) |
| `--name` | Runner name |
| `--region` | Cloud region |
| `--assigned-runner-id` | Which runner executes the deployment |
| `--wait`, `-w` | Wait for job completion |

<Callout type="warn">
  **Deployed runners are available on AWS only.** `infra/templates/runner/` holds one template,
  `aws`, so there is no runner template for GCP, Azure, Alibaba Cloud or Hetzner. Omit
  `--cloud-identity-id` and the picker lists your verified AWS accounts alone. Pass an identity
  for another cloud and the server refuses the deploy before it creates a runner or a job.

  This limits **where the runner itself runs**, not what it provisions: a registered runner
  provisions every cloud Alethia supports, wherever it runs. To run a runner on another cloud, use
  [`alethia runner register`](#alethia-runner-register) — see also
  [self-operated runners](/runner/self-hosted).
</Callout>

## `alethia runner register`

Register a runner you operate yourself. Nothing is provisioned — this is the command for every cloud
`runner deploy` cannot reach.

```bash
alethia runner register my-hetzner-box

# Bound to a cloud account, and machine-readable for a provisioning script
alethia runner register gcp-box-1 --cloud-identity-id <id>
```

| Argument / Flag | Required | Description |
|------|----------|-------------|
| `<name>` | Yes* | Runner name (positional, or `--name`) |
| `--cloud-identity-id` | No | Bind the runner to a cloud account |

It prints the two values the runner process needs, as assignments you can paste straight into an env
file or a systemd unit:

```
✓ Registered runner my-hetzner-box (7f3c…)

ALETHIA_RUNNER_ID=7f3c…
ALETHIA_RUNNER_TOKEN=9a1b…
```

<Callout type="warn">
  **The token is shown once.** Only its SHA-256 is stored, so it cannot be re-read or recovered — a
  leak of the runners table yields nothing usable, and a token you lose is a runner you re-register.
  Copy it before the terminal scrolls.
</Callout>

Then start the runner with those two variables set and confirm it appears in
`alethia runner list` with a recent heartbeat. See
[self-hosted runners](/runner/self-hosted) for the process itself.

## `alethia runner list`

List all runners (status, operator, version, last heartbeat). The **Operator** column shows `managed` or, for self runners, `self · deployed` / `self · registered`.

```bash
alethia runner list
```

## `alethia runner destroy`

Tear down a runner's cloud infrastructure. Queues a `DESTROY_RUNNER` job; another
runner executes the teardown.

```bash
alethia runner destroy --runner-id <id>
```

| Flag | Description |
|------|-------------|
| `--runner-id` | ID of the runner to destroy |
| `--assigned-runner-id` | Which runner executes the teardown |
| `--wait`, `-w` | Wait for job completion |

## `alethia runner remove`

Remove a runner's database record only (no cloud teardown). Run
`alethia runner destroy` first to tear down cloud resources.

```bash
alethia runner remove <runner_id>
```
